## 记录

- [[踩坑-跨盘全量哈希比对被MAX_PATH截断误报内容不同]]（verified，2026-11-25）— 同一份资料在活副本与备份区做逐字节比对，37.8 万文件里最初报「9 条内容不同」，其中 **8 条是假阳性**：备份根路径比活副本长 4 个字符，把临界长文件名顶到 260 字符，普通 `open()` 报 `Errno 2`，脚本把「读失败」降级成「哈希为空 → 记为不同」。加 `\\?\` 前缀重算后 8/8 与活副本 SHA-256 一致，真差异只剩 1 个 `content-manifest.json`。可复用规则：① 跨盘比对前先比两侧根路径长度，长的一侧全程用 `\\?\`；② **读失败永不等于内容不同**，必须独立落 `error.tsv` 并让退出码非 0；③ 差异三分类互斥：仅一侧有 / 内容不同 / 读失败；④ 判「备份完整」要文件数+目录数+总字节+逐文件哈希四项齐对；⑤ Git 等价性要 `rev-parse HEAD` + `HEAD^{tree}` + `ls-files` + `fsck` + `count-objects` 五项同值
- [[经验-百万级文件索引服务的内存与体积优化-mmap零拷贝与砍掉无用SQL索引]]（verified，2026-11-25）— 390 万条目的全盘索引服务，`bytes(mm)` 整份深拷贝让进程工作集涨到 1.9 GB；改成直接用 **`mmap.find`**（C 实现、零拷贝、页面可回收）后降到 **210 MB（降 9 倍）**。另有三个关键点：① `memoryview` 没有 `.find()`，这是当初被迫转 bytes 的直接原因，正解是「在整块 mmap 上按绝对偏移检索 + 用 base/end 限制窗口」；② 偏移表用 `array.array("i"/"I")` 每项 4 字节（390 万项约 47 MB，Python 列表要 340 MB）；③ 索引里的 FTS5 与 `name` 索引是旧 SQL 引擎的遗留物，grep 全部 `SELECT` 确认只剩 `WHERE rid IN (...)`，实测去掉省 **459 MB**、建库从 158 秒降到 **84 秒**（`VACUUM` 后空间才真归还）。含一个静默错误：偏移是相对区域起点的，`_text()` 忘加回 base 会让**所有查询返回 0 条且不报错**，只能靠多语法回归兜住
- [[经验-自建Everything兼容IPC服务顶替原版-四点补齐与伪装常驻]]（verified，2026-11-25）— 想用自建索引顶替原版 Everything 时，调用方判「在不在跑」靠的不是 `WM_COPYDATA` 而是 `WM_USER+n` 身份探测：只实现查询、所有 `WM_USER` 落到 `DefWindowProc` 返回 0，就会永远显示「未检测到 Everything」，而自己写的只发 COPYDATA 的测试客户端却一切正常（假象根源）。补齐版本号/DB 已加载/NTFS 索引等 13 个 code 后 DeskBox 立刻可用（`files=400/3048`）。另含四类必踩坑：宿主要求「进程名 + 窗口类 + 协议」三件套；发送后必须 Pump 消息；`ctypes` 的 `argtypes`（lparam 用 `c_ssize_t`）；`DllImport` 缺 `ExactSpelling` 会把 `FindWindowW` 解析成 `FindWindowWW` 恒返 0。常驻在无管理员权限下不能用计划任务（`Access is denied`），改「启动文件夹 .vbs + 3 秒轮询看门狗」，且 VBS 必须纯 ASCII、`pythonw` 下 `sys.stdout` 为 None 需 `os.dup2` 重定向
- [[踩坑-电源按钮反复变回睡眠且从不真休眠-S0现代待机未转休眠与组策略硬锁]]（verified，2026-11-25）— 「设了休眠却总变回睡眠」是**两层问题叠加**：显示层是方案里四个按钮动作被反复重置为 1（`设置` App 本身就会 reset，证据：`UserModePowerService` ID=12）；行为层是本机固件无 S3、只支持 **S0 现代待机**，而 `HibernateAfterTimeout` 根本没设 ⇒ 按钮进的是 S0 联网待机、永不落盘成真休眠。硬锁用 `HKLM\SOFTWARE\Policies\Microsoft\Power\PowerSettings\<设置GUID>` 写 AC/DCSettingIndex 后，`powercfg /setacvalueindex` 返回 exit 1「存在多个组策略覆盖设置」、注册表直写报「不允许所请求的注册表访问权」，`powercfg /duplicatescheme` 新建方案免写入即为休眠，三重证明锁生效。真休眠靠 `PlatformAoAcOverride=0`（`Session Manager\Power`）+ `HibernateAfterTimeout=600`（`Control\Power`）+ 重启。**两个必踩的坑**：查按钮必须 `powercfg /qh`（`/q` 只显示 1 项）；LID/PBUTTON/SBUTTON 是 `1=睡眠 2=休眠`，而 UIBUTTON_ACTION 是 `0=睡眠 1=休眠 2=关机`，混写会把"休眠"变成"关机"
