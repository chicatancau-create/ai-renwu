fix: 校验改为有界+重试+三态判定，修掉两处「假 MISMATCH」

本轮双推两次都成功（5f6bcbd..f997553 在 gitcode 与 origin 均出现），但校验两次误报：

1) sync-repo.ps1 用无界 ls-remote：经 7890 失败后，直连那次卡满 300 秒返回空 →
   脚本把「读不到」当成不一致，打印 SYNC MISMATCH。
2) 新写的 verify-remote-heads.ps1 首版踩 PowerShell 函数输出污染：函数内
   Write-Output 的诊断行会被一并 return，$o 变成「attempt 1..3」文本而非空串 →
   直连回退分支被跳过（-not $o 为假），且非空字符串让判定落到「real MISMATCH」。
   同一轮 api.github.com 交叉核对 rc=0 且 sha == 本地 HEAD，证明推送其实已落地。

修法：
- 函数内诊断改 Write-Host（host 流，不进返回值）；返回值只允许 40 位 hex sha。
- 读取有界：-c http.lowSpeedLimit=1000 -c http.lowSpeedTime=20，3 次重试 + 3s 间隔。
- 直连回退清 HTTP_PROXY/HTTPS_PROXY/ALL_PROXY（会话 env 可能盖过 config 覆盖）。
- 三态判定：VERIFIED（git 双远端）/ VERIFIED（gitcode 走 git、origin 走 api 交叉核对）
  / UNVERIFIED（读不到，明确不是不一致）/ 真 MISMATCH（都读到且不同）。
- 退出码：0 已验证、2 读不到、1 真不一致；sync-repo.ps1 末尾委托本脚本并透传退出码。
- sync-repo.ps1 的 origin 直连回退推送同样清 env 并加 lowSpeed 上界（60s）。

URL 纪律：远端地址全部取自 git remote 真实配置，交叉核对走 api.github.com；
清代理与 per-command 覆盖只选本机出口，不改全局配置、不替换任何地址。
