# 问题：Tk 自绘面板的两类"看起来像阴影"的视觉瑕疵

## 一句话结论

Tk 的 canvas 图元（`rectangle` / `oval` / `line` / `polygon`）**完全不做抗锯齿**；
而把 RGBA 位图"压到某个底色上再贴"时，**底色写死就会把整张精灵矩形填成不透明色**，
在渐变卡面上必然露出一块平色方块 —— 用户会直接说"为什么有个灰色的阴影"。

## 触发条件与影响

- 项目或功能：桌面悬浮面板 / 自绘仪表盘（本例：Python + tkinter + Pillow，`overrideredirect` 无边框窗口）
- 环境与版本：Python 3.14 + tkinter + Pillow 12；Windows，125% 缩放
- 触发条件：
  1. 用 Tk 图元拼圆角进度条（矩形 + 两端 oval）；
  2. 精灵位图烘焙时传了一个**固定色**作为底材，而它实际压在**渐变色**面板上
- 影响范围：进度条圆头出现 1px 阶梯；卡片下半部的胶囊按钮/暗槽背后出现一块方影

## 复现步骤

1. 前置条件：面板底色是垂直渐变（顶部 `#10131d`，底部约 `#151a26`）
2. 操作：在卡片底部画一个圆角胶囊，精灵用"固定底材 `#10131d`"烘焙
3. 预期结果：胶囊边缘与卡面严丝合缝
4. 实际结果：胶囊背后出现一个**矩形色块**，四角超出圆角轮廓

## 证据

进度条左端逐像素轮廓（同一位置，改前 vs 改后）：

```

 6 ...###############           116 ..o################
 8 ..################            118 ..#################
10 ...###############           120 ..o################

过渡色像素 = 0（零抗锯齿）      过渡色像素 = 6

```

胶囊区域：卡面实测 `(21,31,45)`，而烘图底材写死 `#10131d = (16,19,29)`，
差 `(5,12,16)` —— 足以肉眼看出方影。改成取真实底色后，"等于写死色"的像素 68 → **0**。

## 根因分析

- 已确认的根因：
  1. **Tk 8.x 的 canvas 图元没有抗锯齿**。`oval` 也不会"自带抗锯齿"（这是常见误传）；
     只有图片项（`PhotoImage`，且图像本身带 alpha）才有平滑边缘。
  2. 烘焙函数写成 `out = Image.new('RGBA', (w,h), mat)` + 按 alpha 掩膜 `paste`，
     于是**圆角之外整片保留 `mat` 且 alpha=255** —— 整张精灵矩形变成不透明 `mat` 色。
  3. 卡面是渐变时，写死的 `mat` 只在一个高度上与卡面相等，其余高度都会露馅；
     越靠卡片底部（渐变偏移越大）越明显。
- 排除过的假设：以为是 DWM 的键色镂空（`-transparentcolor`）把抗锯齿中间色抖成棋盘格 ——
  那是**另一个**坑，只在接触镂空区时需要二值化掩膜。
- 问题归属：本次修改引入（设计取舍没覆盖渐变底材）

## 最小修复

1. 所有需要平滑边缘的图元改走 **PIL 4× 超采样**再缩回：
   ```python
   im = Image.new('RGBA', (w*K, h*K), (0,0,0,0))
   ImageDraw.Draw(im).rounded_rectangle([...], radius=r*K, fill=rgba)
   img = im.resize((w, h), Image.LANCZOS)
   ```
2. 烘焙底材**按精灵所在位置的真实底色算**，不要传常量：
   ```python
   def mat_at(y):                       # 与面板渐变同一条公式
       t = (y - card_y) / max(1, card_h - 1)
       base = mix(CARD, mix(CARD, '#33405a', .55), .26 * t)
       if accent:                       # 强调色辉光也要算进去
           v = t * 255
           a = max(0, v*3.2 - 255*2.2) * .055 / 255
           base = mix(base, accent, a)
       return base
   ```
3. 圆角进度条：**左端圆角、右端直角**。右端永远被 knob 盖住，画直角才不会在暗槽中间
   啃出两个缺口；两端都画圆角反而会在槽上戳洞。
4. 进度条底材要在**布局期**算一次并缓存 —— 刷新时"当前卡片"上下文已经变成最后建的那张卡，
   现算会取错底色。

## 可复用规则

- **只要你在 Tk canvas 上画非矩形的东西，就默认它会有锯齿**；要么接受，要么走 PIL 超采样。
- **位图合成的"底材色"是一个物理量，不是一个风格常量**：它必须等于该像素背后**真实**的颜色。
  背景是渐变/图片时，按位置算或直接从底层位图采样。
- 判断"这块方影是不是烘图造成的"：量一下方块内的颜色是否**等于某个写死的常量**，
  再和周围卡面比 —— 相等即坐实。

## 适用范围与不适用范围

- 适用：Tkinter 自绘 UI、任何"RGBA 精灵 + 不透明底材"的合成流程（Qt/SDL 同理）
- 不适用：整块面板本来就不透明且是纯色时，写死底材不会露馅（但一旦改成渐变就会复发）

## 剩余风险

- 超采样是 CPU 开销：大图建议按面积降采样倍率（本项目 `w*h > 12万` 时用 3×）。
- 位图缓存键必须含底材色，否则换底材不会重建（本项目把 `mat` 纳入缓存键）。
