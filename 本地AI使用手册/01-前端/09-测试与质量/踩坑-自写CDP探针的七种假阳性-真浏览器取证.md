# 问题：自己手写的 CDP 探针会造出假 FAIL 和假 PASS，比没有测试更糟

> 七种都在同一次会话里真实发生，且**每一种最初都被我当成「应用的缺陷」**。判据本身要先被证明会失败，才有资格判应用。

## 一句话结论

自写取证探针的失败默认归因顺序应当是：**先怀疑探针的选择器、索引、坐标、日期前提，再怀疑应用**；每条关键断言配一次反向对照，无从执行的断言单独记 `N/E`，不许混进 PASS。

## 触发条件与影响

- 项目或功能：Vue 3 学习习惯打卡应用的端到端验收（登录守卫、周矩阵打卡、增删改、翻周翻月、热力图、404、响应式）
- 环境与版本：Edge 156→157 headless + 手写 CDP 客户端（Node 24 全局 `WebSocket`，无 `ws`）、`vite preview` 服务 `dist/`
- 触发条件：用 `Runtime.evaluate` + `Input.dispatchMouseEvent` 自己写断言，没有 Playwright 的定位器兜底
- 影响范围：51 条断言的整套验收结论；其中 2 条一度被写成「应用有缺陷」并派了修复工人

## 七种假阳性（都附当时的真实读数）

### 1. 属性/通配选择器过宽 → 数量翻倍假 FAIL

```js
document.querySelectorAll('.row, .habit-row, [class*=row]').length   // 报 8
```
`[class*=row]` 同时命中 `.habit-row`（4 个）和 `.row-actions`（4 个）。断言「4 个习惯行」判成 FAIL。
真实结构：`.habit-row`=4、`.cells`=4、`.cell`=28。
**动作**：数量类断言只用一个精确类，且先用一次结构 dump 确认选择器命中数，再写进断言。

### 2. 按可见文本 / `title` 反查元素 → 查到别的行

打卡后想验证同一格子的 `aria-pressed` 翻成 `true`，用 `find(c => c.title === 原title)` 回查。返回 `false`，看着像「状态没翻转」的 bug。
实际：4 行习惯在同一列上有**完全相同的 title**（`10月29日 · 未打卡，点击打卡`），点击后第一行的 title 变了，`find` 于是命中第二行那个仍未打卡的格子。
**动作**：用「行下标 + 列下标」的路径回查（`rows[i].cells[j]`），不要用内容当身份。

### 3. 按 DOM 索引读元素 → `v-if` 让索引左移

`document.querySelectorAll('button')[delIdx].innerText` 读到 `✓`。因为进入删除确认态时 `v-if="!confirmingDelete"` 把同一行的「编辑」按钮**从 DOM 里摘掉**，索引整体左移一位。
连带把下一条真断言也带崩（`第二次确认行数 -1 :: 5 -> 5`，其实是点到了 ✓ 格子）。
**动作**：会随状态增删兄弟节点的区域，一律按文案/属性查，不按索引查。

### 4. 目标在视口之外 → 点了等于没点，还被同名文案蒙成 PASS

统计页很长，明细表在折叠线以下。`getBoundingClientRect()` 给出 `y > 900`，`dispatchMouseEvent` 打在那儿什么都不发生。断言「展开后出现 `.month-detail`」FAIL。
而我配的那条「按钮文案变为收起」用 `/收起/.test(innerText)` 全页搜索 —— 命中了热力图那颗「**收起**色阶图例」按钮，于是真失败被写成 PASS。
**动作**：点击前先 `scrollIntoView({block:'center'})` 再重取矩形；文案类断言要锚定到具体元素（`btn[idx].innerText === '收起'`），不要全页正则。

### 5. 恒真式断言

写排查逻辑时顺手写成 `every(...) === false || true` —— 恒真，永远绿。
**动作**：任何断言若「实现不出它变红的路径」，就是没写。宁可留空也别留恒真。

### 6. 日期 / 数据相关的隐式前提（最隐蔽）

- `check('未来格子被禁用', count > 0)`：2026-11-15 是周日，本周已无未来日期，`disabled=0` → 假 FAIL。应用是对的。
- 同一天里「未来格点击不改变打卡数」变成**空跑**（没有未来格可点），却记成了 PASS。

改成与日期无关的不变量后同一次跑既抓到问题又诚实标注：

```
PASS  未来格子数量等于本周剩余天数且全部 disabled  :: expected=0 perRow=[0,0,0,0] allDisabled=true
N/E   未来格子点击不改变打卡数  :: 本周无未来日期格子（今天是该周最后一天），此断言在当前日期无从执行
```

**动作**：判据写成「量 = f(当前日期/数据)」的等式，而不是 `> 0`；执行不了的走第三档 `N/E`，不并入 PASS。

### 7. 断言写在 JS 模板字符串里，`\d` 被模板转义吃掉 → 匹配数恒 0，看着像应用缺数据

收紧「热力色阶档数」这条时，我把正则写成 `` `...match(/(\d+) 个习惯/)...` `` 放进 `evl()` 的模板字符串。
普通模板字符串会处理转义，`\d` 属于「无法识别的转义」→ 落到浏览器时已经变成字面字母 `d`，于是 `match` 永远返回 null，
断言报 `分布应有档=0 单日最大=0`，第一反应是「热力数据没渲染出来」。实际数据是好的（同一次输出里 `渲染=["heat-0","heat-1","heat-2"]` 就证明格子有内容）。
正确写法是 `\\d`（同文件里另一条 `match(/\\d{4}年\\d{1,2}月/)` 就是这么写的，所以我并非不会，只是漏了一处）。

**动作**：断言字符串里凡是正则元字符，一律双写反斜杠；更稳的做法是**把取数逻辑写成真实 `.js` 模块再 `import`**，而不是塞进 `evl('...')` 的字符串里。
排查同类问题的快捷办法：全文扫「模板字符串内单反斜杠 + 字母」，把合法的 `\n`/`\t` 排除掉——本会话扫出 8 处，7 处是 `\n`、1 处就是上面这个 bug。

## 反向对照：证明断言有牙齿

对「刷新后打卡状态保留」这条，故意抹掉存储再跑一次，确认它确实变红：

```
PASS  刷新后打卡状态保留                :: 16 -> 16
PASS  反向对照：抹掉 localStorage 后同一断言确实失败  :: wiped=15 vs 16
FAIL  负对照（预期 FAIL）：查询不存在的元素  :: 这条必须显示 FAIL，否则说明断言是假的
```

负对照是**故意留一条永远红的**，用来证明「FAIL 这一档真的会输出」。汇总里 `FAIL=1` 就是它；多于 1 才需要查。退出码据此写成 `fail > 1 ? 1 : 0`。

## 证据

- 最终一轮：`PASS=50 FAIL=1（故意的负对照）NOT_EXECUTED=1`，页面异常 0 条，Edge 157.0.4341.60
- 24 个「视口 × 路由」组合横向溢出量与遮挡量均为 0
- 断言日志与实拍图：`E:\fullstack-code\Web\vue\evidence\`（`verify-assertions.txt`、`measure-viewport.txt`、`screenshots/`）
- 可复跑脚本：`E:\fullstack-code\tools\headless-cdp-verify\`

## 根因分析

- 已确认的根因：探针用「内容当身份」「索引当身份」「`>0` 当判据」「全页正则当锚定」「模板字符串里单反斜杠」，都在状态、日期或转义层面失去唯一性/语义
- 排除过的假设：第 1–4 与第 7 条最初都被记成应用缺陷，复核 DOM 结构与源码后全部排除；应用侧真正有问题的只有溢出、遮挡、`.stats` 列宽浮动那几条（见「关联」）
- 问题归属：本次修改引入（探针是我本轮新写的）

## 最小修复

不适用（修的是探针写法，不是产品代码）。七条改写规则见上面每节的「动作」，汇总在「可复用规则」。

## 可复用规则

1. 写第一条断言之前，先跑一次**结构侦察**（dump 选择器命中数 + DOM 树 + 按钮清单），把选择器钉死。
2. 数量断言用精确类；身份回查用路径下标；状态断言锚定到具体元素。
3. 判据写成等式而非 `> 0`，把日期/数据前提显式写进右侧。
4. 每条关键断言配一次反向对照；跑不出红路的断言删掉或标 `N/E`。
5. 汇总固定三档：`PASS / FAIL / N/E`，并预留一条永远红的负对照。
6. 工人报「全绿」或报「你这条 FAIL」后，**我独立复跑一次**再采信——本会话报红的 5 条里有 3 条是探针错，不是工人错。
7. 断言字符串里的正则元字符一律双写反斜杠；能写成真实 `.js` 模块 `import` 进来，就别塞进 `evl('…')` 的字符串。落地后用脚本扫「模板内单反斜杠 + 字母」自查一遍。

## 适用范围与不适用范围

- 适用：任何自写 CDP / 远程协议探针；也适用于 Playwright 里用 `:has-text`、`nth=` 写的定位器
- 不适用：纯单元测试（jsdom/Vitest 里 `querySelector` 的唯一性由测试自己构造，不存在视口与日期前提）

## 剩余风险

- **已做一轮判据自审**（扫转义 + 把 6 条 `>0`/`some()`/`[class*=` 收紧成等式 + 给无从执行的补 `N/E`），但「等式化」只覆盖了我能想到要问的维度；新增断言仍要按同一清单逐条自查，不能因为「这轮查过」就免检。
- 负对照占用 `FAIL` 计数，退出码写成 `fail > 1`；若有人改成 `fail > 0` 就会永远红，若删掉负对照又会让「FAIL 这一档还能输出」失去证据。改动时要同时改退出码，二者绑定。
- 探针的选择器仍写死具体类名，重构 DOM 时会整批失效（属预期，但失效形态是 FAIL 而非报错，容易被误读成产品回归）。
- `N/E` 目前只有 1 条（周日无未来格）。其它日期前提尚未系统枚举，例如「今天是本月 1 号时上一月边界」「种子数据恰好全为已打卡时找不到空格子」——这两类一旦命中会让断言直接抛错而不是报红。
