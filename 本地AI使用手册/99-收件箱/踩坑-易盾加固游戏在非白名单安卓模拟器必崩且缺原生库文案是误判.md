# 问题：易盾加固游戏在非白名单安卓模拟器必崩，「缺少设备原生库」是误判文案

> `needs-review`：复现、根因定位、诊断验证均已完成，但**没有软件修复**——结论是环境层面的（换白名单模拟器），故不升级为 verified 修复记录。诊断本身已实测确认，可作排查参考。

## 一句话结论

网易易盾（NIS）加固的游戏（本次：无悔华夏 `com.syyx.whrhx` v3.8.305）在 ApkStart 自带的官方 Android 模拟器里**必然启动即崩**；ApkStart 弹的「缺少设备原生库（应用可能只提供 ARM 版本），会自动切换兼容镜像重试」是**误判文案**，真因是反作弊白名单只放行 MuMu/雷电等指定模拟器，与 ARM 翻译层、镜像、原生库缺失都无关。

## 触发条件与影响

- 项目或功能：ApkStart（RoutineMiku/apkstart，Electron 壳 + 官方 Android emulator）里启动易盾加固手游。
- 环境与版本：ApkStart 0.4.0→0.5.7；Android 14（API34）x86_64 镜像（google_apis_playstore 与 google_apis 都试过）；宿主 AMD + RTX 5070 Laptop，HypervisorPresent=True。
- 触发条件：游戏进程一启动（`attachBaseContext` 阶段）即崩，约 0.4s 死亡。
- 影响范围：所有用易盾加固且反作弊白名单不含当前模拟器的游戏；ApkStart 内置引擎无法绕过。

## 复现步骤

1. 前置：ApkStart 装好游戏 APK，内置模拟器（任意官方 x86_64 镜像）已启动。
2. 操作：启动游戏（GUI 点启动，或 `adb shell monkey -p com.syyx.whrhx -c android.intent.category.LAUNCHER 1`）。
3. 预期：进入游戏。
4. 实际：进程秒崩，`adb shell pidof com.syyx.whrhx` 为空；logcat 见下。

## 证据

- 真崩溃栈（每次一致）：
  `java.lang.UnsatisfiedLinkError: No implementation found for boolean com.netease.nis.wrapper.MyJni.load(android.app.Application, java.lang.String)`
  `at com.netease.nis.wrapper.MyApplication.attachBaseContext`
- 崩溃前 logcat：`ndk_translation Initialized (aarch64), version 0.2.3`（翻译层正常）；`LoadedApk ClassNotFoundException androidx.core.app.CoreComponentFactory`（壳 dex 未解密，正常现象）；**无任何 dlopen/linker/loadLibrary 报错** ⇒ 不是缺库，是壳在 `JNI_OnLoad` 里静默拒绝 `RegisterNatives`。
- 壳 dex 解密：自写 DEX 反汇编 + base64/XOR 解码，循环密钥 = ASCII `Netease`（fill-array-data payload `4e657465617365`）；壳版本 7.6.3_986；开关 `x86_switch_1` 等。`MyJni.load` 前的门是类名白/黑名单（InstrumentationProxy），**不是设备白名单**——设备检测在 `libnesec.so` native。
- APK 取证：`classes.dex` 仅 61KB 纯壳 stub；`lib/arm64-v8a` 与 `lib/armeabi-v7a` 各 30 个 so，**无 x86 目录**（Unity 游戏 lib 无 x86）；含 `libnesec.so`（明文串 0，加壳）、`libnesec-x86.so`（EM_386）、`libemulator_check.so`（导出 `Java_com_snail_antifake_jni_EmulatorDetectUtil_detect`，Snail 反作弊，独立于 nesec）。
- 硬虚拟化特征（改不动）：`/proc/cpuinfo` flags 含 `hypervisor`(+`vmmcall`)；`ro.hardware`/`ro.boot.hardware=ranchu`；内核 cmdline `androidboot.qemu=1`、`androidboot.hardware=ranchu` 写死在 emulator 二进制；`ro.serialno=EMULATOR37X3X9X0`。
- 易盾检测清单实锤（内存 dump 易盾壳自解密段，来源 https://www.coolapk.com/feed/74666368 ）：root 26 个 su 路径；模拟器 8 家族（MuMu=`com.mumu.launcher/store`、`com.netease.mumu.cloner`、`mumu.config`；Goldfish/QEMU=`/dev/goldfish_pipe`、`ro.kernel.qemu`、`qemu.sf.fake_camera`）；frida/ptrace/maps 注入；属性读 `ro.debuggable/ro.secure/ro.boot.hardware/ro.hardware/ro.build.flavor/ro.build.host/ro.product.manufacturer/name` 等；**不查** test-keys/adb_enabled/LSPosed。易盾 hitType 11=白名单（自有+客户自定义）。

## 根因分析

- 已确认的根因：易盾反作弊在 `libnesec.so` 的 `JNI_OnLoad` 做环境检测，非白名单模拟器 → 不注册 `MyJni.load` 的 native 实现 → Java 层调用必抛 `UnsatisfiedLinkError`。MuMu 能过是因为它在易盾**自有白名单**里（同厂网易），不是因为它「没有虚拟化特征」（MuMu 同样是 qemu）。
- 排除过的假设（全部实测证伪）：
  - 「缺 ARM 原生库/翻译层坏了」→ 翻译层 Initialized 正常，游戏 ARM lib 能加载到壳 JNI_OnLoad；改名 `libndk_translation`→`libnb_translator00`（含 22 个 so 的 DT_NEEDED）翻译层仍正常但游戏照崩。
  - 「换镜像/切兼容镜像」→ playstore 与 google_apis 都崩；ApkStart 承诺的「自动切镜像重试」根本不触发（`installer.js` 条件 `!playImageInfo().ok`，play 镜像已部署 ok=true 恒不切换）。
  - 「-prop 伪装 product 属性」→ AOSP14 init `ro.*` write-once 且 build.prop 后加载覆盖，`-prop` 对 `ro.product.*` 无效；root 改各分区 build.prop 伪装成 Netease/MuMuPlayer-12/mumu + fingerprint/tags/type=user/release-keys + flavor/host/board/soc 全改 → 仍崩。
  - 「hw.hardware=qcom 覆盖 ro.hardware」→ 官方 emulator 忽略，cmdline 仍 ranchu。
  - 「假 MuMu 包名触发白名单」→ AOSP testkey v1 签名 stub 放 priv-app，PM 注册成功（`pm list` 有 com.mumu.launcher/store/cloner）→ 仍崩（白名单可能验签或判别项另在）。
  - 「强制 x86 ABI」→ 游戏无 x86 lib，路线死。
- 问题归属：环境/依赖（游戏反作弊策略），非 ApkStart bug、非本次修改引入。

## 最小修复

无软件修复。可行出路只有两条：① 用易盾白名单内的模拟器（MuMu Player 12 / 雷电）跑该游戏；② 不用 ApkStart 跑易盾加固游戏。本次用户选择彻底卸载 ApkStart（已删 D:\ApkStart、D:\ApkStart-data、%APPDATA%\apkstart、自启动注册表、快捷方式、临时文件，约释放 19.3GB；保留与 Android Studio 共享的 C:\Users\Admin\.android）。
**不要**继续往「改内核抹 hypervisor CPUID / 动游戏保护壳」方向走——那是反作弊对抗/DRM 绕过，且有封号风险。

## 可复用规则

排查「安卓模拟器里游戏启动即崩 / 报缺少设备原生库」时，先抓 logcat 看真实崩溃栈：
- 若是 `com.netease.nis.wrapper.MyJni.load` 的 `UnsatisfiedLinkError` 且**无 dlopen/linker 报错** → 是易盾反作弊白名单拒绝，不是缺库；别在镜像/翻译层/原生库上浪费时间。
- 适用条件：网易易盾加固游戏 + 非 MuMu/雷电模拟器。例外：真正缺 ARM 库会有 linker `dlopen failed` 日志，那才走翻译层/镜像排查。
- 看到 ApkStart「会自动切换兼容镜像重试」文案别当真——其触发条件在 play 镜像已部署时恒不成立。

## 适用范围与不适用范围

- 适用：易盾（NIS）加固手游在第三方/官方安卓模拟器启动失败的归因。
- 不适用：非易盾加固游戏；真有 linker dlopen 失败的缺库场景；MuMu/雷电内的正常运行问题。

## 剩余风险

- 白名单具体判别项未完全逆向（libnesec.so 加壳，静态死路）；「假 MuMu 包名仍崩」未确定是验签还是另有判别项。
- 易盾版本升级可能改变检测面；本结论基于壳 7.6.3_986。
