# 问题：同一个仓库里并行跑多个会话，两个后果都静默

## 一句话结论

① 就算你只 `git add 自己的显式路径`，只要**别人已经把新文件放进过索引**，你的 `git commit` 就会把它一起带走；② 会话之间仓库会被别的会话重构（整目录删除/改名/并入新工程），所以**任何"现状"结论在收尾与归档前必须重新测一遍**，不能沿用本会话早几轮的判断。

## 触发条件与影响

- 项目或功能：一台机器上多个 AI 会话/多人共用同一个 git 工作树（本机 `E:\fullstack-code` 就是这种）
- 环境与版本：Git + Windows + Git Bash
- 触发条件：A 会话 `git add .` 或 IDE 侧暂存了新文件后没提交；B 会话随后 `git add 自己路径` + `git commit`
- 影响范围：B 的提交里混进 A 的文件（提交信息与实际内容不符，交付仓库里出现别人的半成品）；以及 B 收尾时报告的内容早已不在工作树里

## 证据

```
# 搭车现场：B 只 add 了 16 个自己的文件，提交结果却是 17 个
[main 077521d] refactor: UI 收回到课件写法…
 17 files changed, 94 insertions(+), 418 deletions(-)
 create mode 100644 Web/node/class.js        ← A 会话早前暂存的新文件

# 补救后（同一消息重打一次提交）
 16 files changed, 48 insertions(+), 418 deletions(-)
```

```
# 收尾时才发现：工作树里我改的工程已经不存在
$ ls Harmony/
ShoppingMallApp  ShoppingMallApp-ai  harmonyMall-master     # MyApplication 没了
$ git log --oneline -8 | head -3                            # HEAD 已不是我的提交
9edcb3d chore(evidence): P02/P04 证据空库重跑更新并入库 coverage
3d040e1 feat(uni-app): foodlist 列表页实现并引入 uni_modules 组件库
52894fa feat(Harmony): harmonyMall 工程入库
$ git log --diff-filter=D --oneline -1 -- Harmony/MyApplication/entry/src/main/ets/common/UiTokens.ets
5cfac24 refactor: 鸿蒙换成两个商城工程，移除课件工程与音乐工程
$ git log --all --oneline | grep -c "UI 第"                 # 我的提交仍在历史里
```

结论：代码没丢（历史可取），但**工作树里已经没有我改的那份工程**，且承接的新工程里没有我的 `UiTokens.ets`。

## 可复用规则

1. **提交用 pathspec 限定范围**，别依赖"索引里只有我的东西"这个假设：

   ```bash
   git commit -F msg.txt -- 相对路径/我的文件1 相对路径/我的文件2
   ```

   实测：只提交列出的路径，别人 5 条暂存项原样留在索引里。
2. 提交前在**仓库根**看第一列，而不是只看自己目录：`git status --short | grep -v "^ M\|^??"`（第一列非空即"已在索引里"，包括别人的）。
3. 已经搭车了怎么救：`git reset --soft HEAD~1` → `git restore --staged <别人的文件>`（该文件退回未跟踪，内容不动）→ 用原消息重提。操作前先看 `git reflog -3` 确认 `HEAD~1` 就是自己那一次，避免把别人的提交一起回退。
4. **收尾/归档前重测现状**，至少三条：`git log --oneline -8`（HEAD 还是不是我）、`ls` 我改过的目录还在不在、`git log --diff-filter=D --name-only -- <我的路径>`（谁在什么时候删的）。相对时间/mtime 只能判断"是否在被写"，判断不了"现在是什么状态"。
5. 报告里区分三种状态：已提交但工作树已移除（可从历史取回）/ 已提交且在工作树 / 只在工作树未提交。别把"我提交过"写成"现在就是这样"。

## 验证记录

- [x] 搭车复现：同一会话内两次提交，第一次 17 文件含 `Web/node/class.js`，第二次 16 文件不含
- [x] 补救有效：`reset --soft` + `restore --staged` 后，别人的暂存项在 `git status` 里重新出现（` D` 第一列）
- [x] pathspec 提交有效：随后一次 `git commit -- <路径>` 只含 1 个文件，别人 5 条暂存未被动
- [x] 现状核对有效：发现整目录被 `5cfac24` 移除，避免了把"UI 已交付"写进收尾报告

## 适用范围与不适用范围

- 适用：任何多会话/多人共用同一工作树（含 IDE 自动暂存的环境）
- 不适用：独占工作树；也不适用于"必须一次提交含多方改动"的合并提交场景

## 剩余风险

本会话的最终交付物落点需要用户确认：改动都在 git 历史（`a1e76ad`…`c9356fb`）里，但工作树已无该工程；另有一份重打过的提交包 zip 在仓库外（`D:\HarmonyServer\鸿蒙作业-提交包.zip`，与提交时的工作树逐文件比对一致）。若要把改动迁进新工程，得先确认新工程是否要承接这套视觉令牌层。
