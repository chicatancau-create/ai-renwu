# 规则：判"垃圾"之前，先查三类引用

## 一句话结论

一个文件"看起来没用"和"真的没用"是两件事。清理前必须反查三类引用，
任何一类命中就不是垃圾：**① 计划任务 / 自启项是否指向它；② 脚本与文档是否引用它；
③ 它是不是文档里写明的回滚点**。本次实测：6 个 `.bak` 看着像陈年垃圾，
实际是 `rollback.ps1` 的**默认回滚目标**；归档目录里的 `watch.py` 正被计划任务跑着。

## 触发条件与影响

- 项目或功能：清理临时目录、归档旧任务目录、批量删"没用的文件"。
- 环境与版本：Windows 11；项目含计划任务 + `rollback.ps1` + `tmp/` 备份区。
- 触发条件：凭文件名/日期/大小判断"这是垃圾"。
- 影响范围：**删错一次就可能永久失去回滚能力，或让正在运行的服务失效**。
  比"删多占点空间"严重得多。

## 复现步骤（本次实测）

1. 前置条件：项目 `2026-10-10_桌面核心脚本`，`tmp/` 下有 6 个 `.bak`（10-13、10-20 的旧版本快照）。
2. 操作：按"日期旧 = 垃圾"判断，准备删除。
3. 预期结果：释放约 220 KB。
4. 实际结果：**反查后发现不能删** ——
   - `rollback.ps1` 第 138 行：`if (-not $BackupFile) { $BackupFile = Join-Path $Root 'tmp\watch.py.bak-v2.3-final' }`
     → `watch.py.bak-v2.3-final` 是**一键回滚的默认目标**，删了回滚脚本直接报"备份不存在"（exit 2）。
   - `deploy.md` 多处引用 `tmp\watch.py.bak-before-redzone2-20261020`、`watch.py.bak-v2.3-final`。
   - `变更记录.md` 把 `tmp/备份_20261103/`、`tmp/备份_v3.1/`、`tmp/备份_20261111/` 明确写成
     "退回 v3.0 / 退回 v3.1 / 退回 v3.2"的退路。

## 证据

`rollback.ps1` 默认值（原文）：

```
138: if (-not $BackupFile) { $BackupFile = Join-Path $Root 'tmp\watch.py.bak-v2.3-final' }
179: 请用 -BackupFile 指定正确的备份（可用：tmp\watch.py.bak-*）
```

活体依赖（原文）：

```
计划任务 WindowCenter State = Running
Action = D:\PyCharm\Python\pythonw.exe "G:\AIrenwu\01_任务归档\2026-10-10_桌面核心脚本\03_工具脚本\watch.py"
进程   PID=38992 ... 同一路径
```

→ 该目录虽已"归档"，仍是**生产活体**。删目录 = 监视器失效（且任务下次启动也找不到文件）。

## 根因分析

- 已确认的根因：**"归档"不等于"废弃"**。归档只改变了位置，不改变引用关系；
  引用关系是分散的（计划任务、Run 键、脚本默认值、文档正文），不集中在文件本身。
- 排除过的假设：不是"备份太旧就该删"（旧版本恰恰是回滚退路）、
  不是"目录叫 tmp 就是临时垃圾"（项目把 tmp 当受管备份区用）。
- 问题归属：清理流程缺少"引用反查"这一步。

## 最小修复（清理前的固定动作）

**三步反查，任一命中即标记"不可删"：**

```bash
# ① 计划任务 / 自启项 是否指向该路径
Get-ScheduledTask | ForEach-Object {
  $_.Actions | Where-Object { $_.Arguments -like "*<路径片段>*" } |
    ForEach-Object { "$($_.Execute) $($_.Arguments)" }
}
Get-ItemProperty "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run" |
  Select-Object * -ExcludeProperty PS* | Format-List

# ② 脚本 / 文档 是否引用
grep -rn "<文件名或目录名>" <项目目录> --include=*.ps1 --include=*.py --include=*.md

# ③ 是否为文档写明的回滚点
grep -rn "回滚\|rollback\|退回" <项目目录> --include=*.md
```

**只删"三类都不命中"的**。本次按此判定，真正的垃圾只有：
`__pycache__`（纯缓存，自动重建）+ 一份经哈希证实逐字节相同的重复副本（`备份_v3.1/_verify`）。
合计约 600 KB，其余全部保留。

## 可复用规则

1. **先反查、后删除**。反查清单固定三项：计划任务/自启项、脚本/文档引用、回滚点。
2. **归档 ≠ 废弃**。把目录移进 `01_任务归档` 前，先确认没有计划任务/Run 键指向它；
   若有，要么改引用，要么明确"这是活体，不得移动"。
3. **备份按"文档是否引用"判，不按日期判**。被 `rollback` 脚本或变更记录引用的，多旧都要留。
4. **重复副本用哈希确认再删**，别靠文件名相似。
5. `__pycache__` / `.pyc` / 缩略图缓存这类**可自动重建**的，才是无条件可删的。

## 适用范围与不适用范围

- 适用：任何带计划任务/服务/回滚机制的项目目录清理与归档。
- 不适用：纯一次性产出目录（无引用、无回滚设计）—— 那类按日期清理即可。

## 剩余风险

- 反查①②依赖"引用写在可搜索的文本里"。若引用藏在编译产物、快捷方式（`.lnk` 二进制）、
  或注册表其它位置，grep 会漏。**本机已踩过同类坑**：删"全是联接"的目录会跟随联接
  回收真源（见 [[踩坑-删联接目录会跟随联接回收真源须靠回收站元数据取证]]）。
  对含联接/快捷方式的目录，还要单独查联接目标。
- 计划任务的反查用 `Arguments -like` 匹配，路径大小写/短名（8.3）可能漏，建议同时按文件名匹配。
