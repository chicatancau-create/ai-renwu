# 规则：把口语需求翻译成 a/b/c 判定，再写代码；注释与代码不一致必须当 bug 处理

> `verified`：2026-10-19 在窗口居中项目里实际踩到并修复；过程记录见「本轮自省」。

## 一句话结论

用户的口语需求（"左右要有空格，上下也要有空格"）必须先落成**可断言的判定式**，
再写代码；改完后**逐条核对"注释说的"和"代码做的"是否一致** ——
那次 "框高 = 工作区×上限 − 2×留白" 的注释底下，代码根本没减留白，
是所有缺陷里最难靠"跑一下看看"发现的一类。

## 触发条件与影响

- 项目或功能：任何"规则/阈值/布局"类需求（窗口尺寸、分页、限流、布局栅格）
- 环境与版本：与本机无关，属通用工程规范
- 触发条件：需求用口语描述，且实现涉及多个阈值（上限、下限、比例）
- 影响范围：不报错、不崩溃，**结果只是"看起来差不多"**，最容易签收后发现不对

## 复现步骤

1. 口语需求："居中，但上下也要留白"
2. 写法 A（错误）：按宽度缩到 3/4，高度跟随比例 —— 16:9 窗口高度也只剩 3/4，上下仅 13%
3. 写法 B（错误）：加了高度上限，但注释写"已扣留白"、代码只取 `工作区 × shrink_h_to`
   → 高度卡上限的窗口上下只剩 7.99%，与注释承诺不符
4. 写法 C（正确）：先写死 a/b/c 三条，再让代码逐条实现，最后用测试锁住

## 证据

```
用户原话: "我需要的是居中，前提是虽然左右两边有空格，上下也要有空格，
          你全部上下粘一块的话也不好看啊"

实际日志（旧规则）:
  22:03 WeChatAppEx.exe 1282x1017 -> 1920x1523  顶部 8px / 底部 9px
  22:06 clash-verge.exe 1550x1283 -> 1860x1540  顶/底 = 0
  21:48 clash-verge.exe 1550x929  -> 1920x1151  上下各 194（12.6%）

修复后（同一工作区 2560x1540）:
  1282x1017 -> 1631x1294  左右 464  上下 123
  1550x1283 -> 1563x1294  左右 498  上下 123
  1550x929  -> 1920x1151  左右 320  上下 194
```

最终写死的判定（代码与注释、测试三处一致）：

```
a) 宽 ≤ 工作区 × shrink_frac
b) 原尺寸居中时左右留白 ≥ 工作区 × min_gap_frac_w
c) 原尺寸居中时上下留白 ≥ 工作区 × min_gap_frac_h
a+b+c 全满足 → 尺寸不动，只居中
否则 → 等比缩到"工作区扣掉四边留白 ∩ 宽高上限"内（只缩不放）
```

## 根因分析

- 已确认的根因：需求是口语的，实现是"边改边试"的；注释描述了一个更好的版本，
  代码停在半路，而两者都没被测试校验，于是缺陷长期潜伏。
- 排除过的假设：
  - "是窗口自己改回去"→ 否：日志显示目标值本身就不对。
  - "是 DPI/多屏"→ 否：工作区与坐标全程一致（已 DPI-aware）。
- 问题归属：本次修改引入。

## 最小修复

1. 把需求转成 a/b/c 判定式，写进函数 docstring **第一段**（不要写在末尾的"历史沿革"里）。
2. 代码里每个阈值只在一个地方出现，且变量名就是判定式里的词（`min_gap_y`、`room_h`）。
3. 注释里出现的公式，必须能在下一行代码里逐项找到；找不到就是 bug。
4. 用测试锁住 a/b/c，而不是只测"结果看起来对"。

## 本轮自省（必须记，避免只写成功面）

这次修复我改了 **4 稿**才对：

| 稿次 | 错误 | 被什么抓住 |

教训：**规则类改动必须先写死语义（a/b/c），再用测试锁住，不要边改边凭感觉调整。**

## 可复用规则

1. 接到口语规则需求，第一步产出 **判定式**（a/b/c），写在 docstring 首段。
2. 改完对着注释逐项找代码；**注释里的公式在代码里找不到 = bug**。
3. 每个阈值只允许一处定义，变量名与判定式用词一致。
4. 测试断言要覆盖"边界刚好"的情形（本例：正好半屏、正好上限、正好留白下限）。
5. 自己改了几稿就记几稿——错误稿次与原因是最有价值的经验。

## 适用范围与不适用范围

- 适用：任何带阈值/比例/布局的业务规则改动。
- 不适用：纯重构（行为不变）且已有充分测试覆盖的场合，可跳过判定式书写。

## 剩余风险

人工"逐项核对注释"容易漏；若项目有 CI，建议加一条"docstring 里出现的常量名必须在函数体内被引用"的检查。
