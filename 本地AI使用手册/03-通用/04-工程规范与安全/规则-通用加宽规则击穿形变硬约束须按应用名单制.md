# 问题：把一个"某应用窗口太窄"的修复写成通用规则，1499 例约束测试立刻大面积报红

> verified：通用版实测 15/19（4 个套件红），撤回后名单版 19/19 全绿且 31 条断言通过。

## 一句话结论

"窗口竖向太窄"是**形状特征**，但"这个应用接受被拉宽"是**应用属性**——形状推不出属性。加宽＝故意违反"保持宽高比"这条硬约束，因此只能对**确知能自适应宽度**的进程逐个登记（白名单），不能按几何条件泛化。泛化前先跑最极端的那组约束测试：如果它被大面积击穿，方向就错了，不是阈值没调好。

## 触发条件与影响

- 项目或功能：`G:\AIrenwu\01_任务归档\2026-10-10_桌面核心脚本\03_工具脚本\watch.py` 的 `target_rect()`（窗口落位决策）
- 环境与版本：Windows 11；监视器 v3.6；`zone_w=0.86 / zone_h=0.87`（红圈 2202×1340）、`stretch_tol=1.25`、`small_frac=0.45/0.40`
- 触发条件：用户报"某软件打开还是窄竖条"（WorkBuddy AI 自己开成 1112×1340，左右各空 ~700px，留白比 7:1）
- 影响范围：
  - 泛化版会把竖屏视频、手机镜像、竖长工具栏一起横拉，破坏内容显示
  - 会推翻已存在的"形变系数 ≤ 1.25"全局硬约束，等于悄悄废掉一个质量保证
  - 撤回成本高（波及 4 个测试套件）

## 复现步骤

1. 前置条件：已完成微信的单应用加宽（`wide_apps` 名单制）并全量通过
2. 操作：把加宽改成通用规则 —— 凡 `h >= wa_h*small_h_frac` 且按等比算出的宽度 `< zone_w*0.62`，就把宽度拉到 `zone_w*0.78`、高度撑满红圈
3. 预期结果：新应用被修好，旧测试不受影响
4. 实际结果：全量 **15/19**，4 个套件报红

## 根因分析

- 已确认的根因：把"形状"当成了"属性"。竖长窗口有两类意图完全不同的来源：
  - 可自适应宽度的应用（聊天/IDE/AI 面板）—— 拉宽是改善
  - 内容本身就是竖向的（竖屏视频、手机投屏、竖长工具栏、竖排文档）—— 拉宽是破坏
  两者在几何特征上**不可区分**，只能靠进程名/应用身份区分。
- 排除过的假设：
  - 不是阈值没调好：把 gate 从 0.62 调到 0.5 会同时放过更多竖屏内容，且 1499 例里被击穿的是 deform 约束，与 gate 无关。
  - 不是"测试太严"：deform ≤ 1.25 是产品既定要求（避免明显形变），不能为一条新规则让路。
- 问题归属：本次修改引入（设计层面的过度泛化）。

## 最小修复

名单制：只在 `watch.json` 的 `wide_apps` 里登记确认可加宽的进程，`target_rect()` 里只保留一条分支：

```python
frac = wide_apps.get(proc_name)          # 名单外 → None → 走原有三档
if frac and h >= wa_h * small_h_frac:
    new_w = int(round(zone_w * frac)); new_h = zone_h
    mode = "加宽居中"
```

当前 4 项：`Weixin.exe / WeChat.exe / WorkBuddyAI.exe / WorkBuddy.exe` 均为 `0.78`。

**幂等性必须一起验证**（否则每轮轮询都会重新触发一次）：加宽后 1718×1340 的宽已 ≥ `zone_w*0.62`，且形变系数 1.28 > `stretch_tol`，会稳定走"按原比例装进红圈"档，`fit(1718,1340)` 反算回 1718×1340 —— 同一个不动点。测试里专门有两条幂等用例。

新应用犯同样毛病时，只需加一行 `"进程名.exe": 0.78`。

## 可复用规则

1. **涉及"故意违反既有不变式"的优化，一律按对象登记（白名单/映射表），不按形状或统计特征泛化。**
2. 泛化一个修复前，先跑那组"最极端、例子最多"的约束测试（本例 1499 例）；**它被大面积击穿 = 方向错**，不要再调参。
3. 配置里必须写清"为什么是名单不是规则"，并留下撤回记录（本例注释里写明通用版实现过、被哪两个测试否决），否则下一个人（或下一个会话的我）会重犯。
4. 白名单条目要带"默认倍数 + 如何新增一行"的说明，让后续维护成本降到最低。
5. 修完必须验**幂等**：轮询型程序每轮都会重新决策，规则必须收敛到不动点。

## 适用范围与不适用范围

- 适用：任何"按几何/统计特征决定是否干预内容呈现"的场景：窗口尺寸、图片裁剪、表格列宽、视频缩放、字体自适。
- 不适用：特征与意图一一对应的场合（例如"文件名后缀 .mp4 就是视频"），这类可以按特征泛化。

## 剩余风险

- 名单制依赖进程名稳定；应用升级改 exe 名（如国际版 `WorkBuddy.exe` vs 国内版 `WorkBuddyAI.exe`）需同步补登记，否则静默退回窄条（且**不留日志**）。
- 同一应用的不同窗口（主窗 + 小浮窗）需要尺寸门槛（`h >= wa_h*small_h_frac`）兜住，否则小窗会被硬撑到红圈大小。
- 倍数 0.78 是审美取值，无客观最优；用户再提"太窄/太宽"只需调这一个数。
