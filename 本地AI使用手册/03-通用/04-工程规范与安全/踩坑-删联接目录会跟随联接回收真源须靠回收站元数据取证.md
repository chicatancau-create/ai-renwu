# 踩坑：用资源管理器删「全是联接」的目录，会把联接目标里的真实文件一起删掉

## 一句话结论

`D:\Skills-active` 里全是指向 `D:\Skills\<名>` 的 Junction，
**用 Windows shell（资源管理器 / SHFileOperation）删它时会跟随联接，把真源文件一起送进回收站**；
一晚上发生三次，技能库被清空。
判据：**文件进了回收站 ⇒ 是 shell 删除，不是 `shutil.rmtree`**（后者不进回收站）。
恢复靠解析回收站 `$I` 元数据拿回原路径，逐个原样还原。

## 触发条件与影响

- 环境：Windows，NTFS Junction（`st_reparse_tag == 0xA0000003`）。
- 触发：任何「清理/搬迁」动作对**内容为联接**的目录做递归删除或移动。
  本机是另一个工具在批量搬迁 agent home（改名成 `.<name>.__moving` staging）时踩到。
- 影响：`D:\Skills\headroom` 与 `D:\Skills\skill-router` 变成空目录（12 个文件全没）；
  因为 12 个 agent 技能根里的同名条目**都是指向这两个目标的联接**，所以无一幸免，
  所有 Agent 同时失去这两个技能。

## 证据（取证方法本身可复用）

解析回收站 `D:\$RECYCLE.BIN\<SID>\$I*` 文件：
头部 8 字节 version（=2）、8 字节原始大小、8 字节 FILETIME 删除时刻、之后是 UTF-16 原路径。
对应的实体是同目录下同名的 `$R*` 文件。

- 15 条全部删除于 **`02:04:06.485–06.951`（0.5 秒内一次批量操作）**，
  原路径正是 `D:\Skills-active\{headroom,skill-router,2 个迁移 JSON}` **加上联接目标里的真实文件**。
- 后续两次：`02:22:56–59`、`02:23:43–44`；`02:15` 之后共 **13467 条删除**，
  涉及 `.cc-switch/.lingma/.zcode/.qoder-cli/.openclaw/.kimi-code/.continue` 等被改名 staging 的 home。
- 同期外部操作：`02:04:32 cc-switch detach`、`02:04:54 claude 转 direct 且 BASE_URL 换成
  `https://api.pateway.ai/v1`（换供应商）→ 判定是用户/另一个 AI 在 GUI 里改配置并顺手清理。
- **我自己的脚本不删文件、也不走 shell，可排除。**

## 根因分析

- 已确认根因：Windows shell 的递归删除会跟随 Junction 进入目标目录。
- 排除过的假设：我的 Python 脚本误删（`shutil.rmtree` 不进回收站，且脚本里没有删除逻辑）；
  自愈盾误覆盖（读源码确认它只在文件缺失/0 字节时还原，**从不删除、从不覆盖非空文件**）。
- 问题归属：环境或依赖（shell 语义）+ 架构风险（联接把「唯一真源」也变成了「唯一毁灭点」）。

## 可复用规则

1. **绝不要用资源管理器删「内容为联接」的目录**（本机是 `D:\Skills-active` 与各 agent 技能根）。
   要清理就用脚本**只删联接本身**（`os.rmdir` 对联接不会进入目标），或先摘联接再动目录。
2. **批量搬迁 agent home 前，先把技能根里的联接摘掉**，搬完再重建。
3. 改接技能根**只能 inject**（加/删技能联接），**绝不 rmdir 根目录重建**——
   WorkBuddy 会往技能根写应用状态 JSON，重建会把它们搬走。
4. 判「谁删的」：**进回收站 ⇒ shell 删除；不进回收站 ⇒ 程序删除**。
   再用 `$I` 的 FILETIME 聚簇判断是不是一次批量操作（0.5 秒内十几条 = 一次）。
5. **联接给了「唯一真源」，也给了「唯一毁灭点」**。凡是用联接共享的唯一数据，
   都要在联接图之外留一份真实镜像 + 自愈循环；镜像很小（本机 0.15MB），别为省空间删掉。
6. 判 Junction 用 `getattr(os.lstat(p), "st_reparse_tag", 0)`（`0xA0000003`=Junction、`0xA000000C`=Symlink）；
   **`os.path.islink()` 对 Junction 返回 False，不可用**；PowerShell `Get-Item .LinkType` 有时返回空但
   `.Target` 有值，也不可靠。
7. 用 `os.path.isdir()` 过滤技能根子项**会漏掉断链 Junction**，必须先判 reparse 再判 isdir。

## 适用范围与不适用范围

- 适用：Windows 上任何用 Junction/Symlink 共享唯一数据源的布局。
- 不适用：硬链接（语义不同）；Linux bind mount。

## 剩余风险

- 自愈盾 20 秒一轮，秒级连删仍可能丢掉「刚写还没镜像」的文件 → 回收站取证是最后一道。
- 回收站被清空后无法用此法恢复；镜像 + git 远端是另两道。
