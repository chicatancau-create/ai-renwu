# 问题：会话结束后清理时，最新导出件已经不等于用户正在使用的交付件

> `verified`：本轮在已归档 PPT 工程中实测到交付件与最新导出件的页数、大小和 MD5 均不同；按新流程清理后交付件字节未变。

## 一句话结论

清理「会话垃圾」前必须先比较 **交付件 ↔ 最新导出原件**；只要用户已经手工编辑交付件，最新导出件也只是历史生成源，绝不能拿它覆盖、重命名或回滚当前交付。

## 触发条件与影响

- 项目或功能：跨会话续接、归档任务清理、重新导出后覆盖交付件。
- 环境与版本：Windows 10.0.28000，Microsoft PowerPoint，`python-pptx`，PPTX 工程。
- 触发条件：会话记录写着「交付件与最新导出件 MD5 相同」，但交付件在会话后被用户继续编辑。
- 影响范围：直接覆盖会丢失用户新增页、改页和批注；只按记录判断还会把「导出件与交付件不一致」误判成清理失败。

## 复现步骤

1. 前置条件：工程已有最终交付件与最新导出原件，历史记录称两者 MD5 相同。
2. 操作或命令：

```powershell
Get-FileHash -Algorithm MD5 <交付件>
Get-FileHash -Algorithm MD5 <最新导出件>
```

3. 预期结果：两者 MD5 相同，最新导出件可代表当前交付状态。
4. 实际结果：

```text
交付件：4,640,480 bytes / MD5 a52990eee3b626269e9256d0461bf179 / 11 slides
最新导出件：4,612,778 bytes / MD5 30d342ec66ef07569b128ff3ea5d2643 / 10 slides
```

5. 进一步用 `python-pptx` 递归统计形状，发现交付件第 3 页完全没有形状，是用户后来插入的空白页；工程导出链仍只有原 10 页。

## 证据

- 交付件 mtime：`2026-11-10 18:36:35`，晚于会话生成时间。
- 交付件结构：`slides=11 | pictures=18 | charts=4 | notes=10`。
- 最新导出件结构：`slides=10 | pictures=18 | charts=4 | notes=10`。
- 第 3 页递归遍历结果为 0 个形状；第 4 页开始才是原工程第 3 页内容。
- 清理后交付件哈希未变，只删除工程 `exports/backup/validation` 中未被当前交付引用的历史中间件。

## 根因分析

- 已确认的根因：会话记录描述的是**生成当时**的一致性；交付件离开生成链后仍可被用户独立修改，记录不会自动失效。
- 排除过的假设：不是 workspace 移动导致哈希变化；移动只改变路径，不改变文件内容。
- 问题归属：清理流程缺少「当前交付件是否仍是生成件」的复核步骤。

## 最小修复

清理前固定做四层比较：

1. 路径与 mtime：确认交付件是否在会话后变化。
2. 大小与 MD5：确认交付件是否仍等于最新导出件。
3. 页数与结构：用 `python-pptx` 递归统计 slides、pictures、charts、notes 和每页形状。
4. 意图检查：发现空白页或用户新增页时，只报告，不自动删除、不自动覆盖。

删除范围只限工程中间件：

- 保留：最终交付件、最新导出原件、最新 SVG backup、当前质量/校准报告、被脚本引用的工具。
- 删除：旧导出件、旧 backup、旧 validation report，且先反查计划任务、脚本和文档引用。

## 验证记录

- [x] 静态比较：交付件与最新导出件大小、MD5、页数均不同，确认不能反向覆盖。
- [x] 结构检查：递归遍历确认交付件第 3 页为 0 形状，属于用户后续插入。
- [x] 引用反查：无计划任务/Run 引用；当前脚本只引用最新导出件。
- [x] 清理结果：删除 46 个历史中间件，释放 `59.1 MB`。
- [x] 交付件守恒：清理后交付件仍为 `4,640,480 bytes / MD5 a52990eee3b626269e9256d0461bf179`，未被覆盖。

## 可复用规则

1. **会话记录里的「MD5 相同」只证明生成当时，不证明现在仍相同。** 每次清理前重新测。
2. **最新导出件不是交付件的权威副本。** 用户手工编辑后，交付件才是权威。
3. **发现页数不同或空白页，先报告，不擅自删除。** 空白页可能是用户故意留的占位。
4. **清理中间件采用白名单**：只保留最新一套，其他历史导出/备份/报告在引用反查后删除。
5. **清理后必须复测交付件哈希**，证明只删了工程垃圾，没有碰当前交付。

## 适用范围与不适用范围

- 适用：PPT/Word/Excel 等由脚本生成、随后可能被用户继续编辑的交付物；也适用于其他「生成件 + 交付件」双副本工程。
- 不适用：交付件本身就是唯一导出件且从未被手工修改的场景；此时最新导出件与交付件应保持一致，但仍需哈希复核。

## 剩余风险

- 本轮只实测 PowerPoint/PPTX；Word/Excel 的 COM 或 Office 自动恢复是否会造成同类漂移，尚未跨应用复现。
- 用户插入的空白页仍保留在交付件中；是否删除属于内容决定，不由清理流程自动判断。
