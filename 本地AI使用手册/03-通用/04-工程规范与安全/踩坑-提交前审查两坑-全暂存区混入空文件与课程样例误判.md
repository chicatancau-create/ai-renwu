# 问题：提交前审查的两个独立坑，都会让「云端项目 ≠ 本地项目」

## 一句话结论

① `git commit` 提交的是**整个暂存区**：预先暂存的 0 字节空文件会被顺带进无关提交（状态 `AM` = 暂存版 ≠ 工作区版）；
② 「看起来是运行时产物」的文件（如 `uploads/`）可能是**课程代码直接依赖的固定样例**——排除前先 grep 引用。
两坑都在 2026-11-13 三仓库提交会话中实际遇到；验收标准是「云端克隆后能构建/运行/验收，与本地一致」。

## 坑 1：全暂存区特性顺带预暂存空文件

- 现场：`E:\fullstack-code` 的 `Harmony/harmonyMall-master/entry/src/main/ets/pages/me/RegPage.ets` 与
  `pages/test/DialogPage.ets` 长期状态 `AM`——**暂存区是 0 字节**，工作区有 138/48 行。
- 事故：第一个提交（97241b0，chore 忽略 .memsearch）没打算碰这两个文件，但 `git commit` 提交整个暂存区，
  把两个空文件顺带了进去（3 files changed, 3 insertions）。
- 修复：第三个提交（52894fa）前重新 `git add`，用 `git diff --cached --numstat` 验证暂存 138/48 行再提交；
  最终 `git cat-file -s HEAD:<path>` 验证 3648/1021 字节非空。
- 决策：**不为美观改写历史**——双远端（GitCode+GitHub）force push 的代价大于收益；保证最终树正确并用 cat-file 验证。

## 坑 2：「运行时产物」误判差点排除课程样例

- 现场：`Web/node/uploads/a.txt`（9B）与 `uploads/avatars/2025/a.txt`（6B）初判为运行时上传产物，准备排除。
- 反转证据：预检 grep 发现 `E:\fullstack-code\Web\node\molu.js:14` `await fsp.stat("./uploads/a.txt")`，
  且**全仓库没有任何代码创建该文件** → 它是课程固定样例，排除后云端代码直接跑不起来。
- 修复：改判为提交（4fff672），提交信息里写明样例性质。

## 可复用规则

1. 提交前必看 `git diff --cached --stat`（或 --name-only）；`AM` 状态的文件必须重新 add 再提交。
2. 排除疑似运行时产物前先 grep 代码引用：**代码读它 + 没有代码生成它 = 样例，必须入库**；
   代码读它 + 代码也生成它 = 真产物，可忽略。
3. 云端完整性判据 = 克隆后能构建/运行/验收；有意的排除只应是隐私数据（如 `.memsearch/`）与可再生产物（按仓库既有忽略规则）。
4. 提交后用 `git cat-file -s` / `ls-remote` 头比对验证最终树，别把「提交成功」当「内容正确」。

## 适用范围与不适用范围

- 适用：任何有「云端检测 / 多远端交付」要求的仓库提交前审查；尤其暂存区长期未动的课程仓库。
- 不适用：纯本地实验仓库（无云端一致性要求）。
