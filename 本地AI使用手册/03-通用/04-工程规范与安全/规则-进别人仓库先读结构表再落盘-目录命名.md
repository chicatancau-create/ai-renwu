# 问题：把单文件网页建在了仓库根目录，被要求返工搬家

## 一句话结论

**目录名代表"那条线是什么"，不是"这次做了什么"**；落盘前先读仓库自己的结构文档（README 的目录表、
`AGENTS.md`、`progress.md`），按已有分类线归位。根目录不是任务暂存区。

## 触发条件与影响

- 项目或功能：`E:\fullstack-code`（按语言分线的多语言学习仓库：`Web/ Cpp/ Python/ Harmony/`）
- 环境与版本：main 分支，git 跟踪中文路径
- 触发条件：新建交付物时只想着"这个任务叫什么"，直接建 `resin-island/`
- 影响范围：被用户纠正两次（"你不要乱取名字，每一个文件夹都对应着一个东西"），需要搬家 + 改文档 + 重新验证

## 复现步骤

1. 前置条件：一个已有分类约定的仓库
2. 操作或命令：`mkdir <任务名> && 写文件`
3. 预期结果：产物被接受
4. 实际结果：位置错误，需要 `git mv` 返工；且结构文档与实际不一致会误导下一个进来的人

## 证据

- 返工前后对照：`resin-island/index.html`（根目录，任务名）→ `Web/webgl自学/浮空树脂小岛.html`（语言线 + 命名法对齐）
- 仓库自身约定：README 的「目录结构」表 + `Web/js自学/`（免构建、浏览器直开的独立 HTML 页）与
  `Web/vue/`（要 npm 构建的工程）两条现存分类
- `git -c core.quotepath=false status` 复核：搬家后索引里只剩预期路径，工作区没有多余改动

## 根因分析

- 已确认的根因：动手前没读仓库的结构文档，用"任务视角"代替"仓库视角"。
- 排除过的假设：不是仓库缺文档（README 表 + progress.md 都写得很清楚）；不是没有合适位置（`Web/` 就是那条线）。
- 问题归属：本次修改引入

## 最小修复

规则（下次可直接执行）：

1. **先归类再落盘**：读 README 结构表 / `AGENTS.md` / `progress.md`，把产物归进已有分类线；
   确实不属于任何一类时先提出来讨论，不要自己造平行顶层目录。
2. **目录名 = 那条线是什么**。本例是免构建单文件网页 → 与 `js自学` 同级另起 `webgl自学/`
   （沿用"技术名 + 自学"命名法），而不是塞进 `js自学` 破坏它"语法笔记"的定位。
3. **文件名跟同级风格走**。那条线的独立页面用内容中文名，所以叫 `浮空树脂小岛.html` 而不是 `index.html`——
   同一条线以后加第二、第三个页面不撞名。
4. **结构变了同步改结构文档**（README 表 + 进度文档），否则错误会被下一个人复制。
5. **搬已跟踪的文件用 `git mv` 且只针对具体路径**；绝不 `git add -A` / `git add <目录>`——
   仓库里可能常驻别人的未提交改动，会被一起卷进提交。暂存后 `git status --short` 数一遍是否只有自己那几行。
6. 中文路径判"还在不在索引里"要加 `-c core.quotepath=false`，否则默认八进制转义会让 grep 假性找不到。

## 验证记录

- [x] `git mv` 后 `git status`：`R resin-island/index.html -> Web/webgl自学/浮空树脂小岛.html`，根目录无残留
- [x] 文档同步：README 目录表 + 运行说明、progress.md 结构表各加一行
- [x] 搬家后重新取证：`file://` 直开新路径可跑、无 console 报错（见关联记录）
- [ ] 构建 / 测试：本任务无这些环节，未执行

## 可复用规则

在任何非空仓库里新增文件前，先回答三个问题：**这条线叫什么？同级目录怎么命名？结构文档在哪？**
答不出就先读 README/AGENTS，再动手。
例外：全新空仓库可以自定结构，但一开始就要把结构写进 README，否则等于没约定。

## 适用范围与不适用范围

- 适用：有既有约定的团队仓库、个人多语言练习仓库、任何"我不是唯一使用者"的目录树
- 不适用：一次性 scratch 目录（应放在工作区外，例如系统 TEMP，而不是仓库里）

## 剩余风险

- 若仓库自身结构文档与实际不符，"照文档归位"可能仍会放错；此时以 `git log` 里同类文件的实际落点为准。
