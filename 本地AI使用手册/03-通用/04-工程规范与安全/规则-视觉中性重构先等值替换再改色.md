# 问题：视觉中性重构用等值替换：令牌值先等于原字面量，改色另作视觉决策

## 一句话结论

把写死颜色/尺寸收口成设计令牌时，**先令令牌值等于原字面量值再替换引用**，整批改动就是纯改名、零视觉差，同状态截图配对自然通过；「收口」与「改色」混在一次提交里会让视觉回归无法归因。

## 触发条件与影响

- 项目或功能：UI 令牌化收口（本机 CodeWeave 应用端 QML 29 处写死颜色收口）。
- 环境与版本：Qt 6.8 QML + DesignSystem 令牌单例；验收靠同状态截图配对。
- 触发条件：审查要求「颜色一律走令牌」，执行方顺手把颜色也调成「更合理」的值。
- 影响范围：视觉验收失败且无法区分「重构引入」还是「改色引入」;返工成本高。

## 复现步骤

1. 前置条件：存在 N 处写死字面量与同状态截图基线。
2. 操作：收口时同时调整若干颜色值。
3. 预期：截图配对通过。
4. 实际：配对出现差异，无法归因；若只做了等值替换则差异为 0。

## 证据

- 执行方按等值手法收口后，审查方抽查 5 个原字面量（`Qt.rgba(220/255,233/255,251/255,0.014)`、`Qt.rgba(141/255,155/255,172/255,0.4)`、`Qt.rgba(32/255,36/255,43/255,0.5)`、`#0b1b27`、`#141b23`）**原样进入 DesignSystem.qml**；令牌总数 113；全 QML（除 DesignSystem）写死颜色 29→0。
- 改动后重跑门禁：Qt CTest 11/11（126.14s，含 qt-qml-load）、Web 87 文件/1296 项全绿，无渲染回归。
- 对照：同轮拆分对照批用「相邻提交 + 同一修补 + 重复运行估噪声」方法，证明等值/中性改动的截图差异可控制在运行噪声量级（每通道最大差 1/255）。

## 根因分析

- 已确认的根因：视觉回归的归因需要「单变量」；收口+改色双变量使配对失效。
- 排除过的假设：不是令牌机制本身有问题（等值替换后门禁与截图均通过）。
- 问题归属：重构方法（修改前已存在的认知陷阱）。

## 最小修复

两步分离：① 等值收口（令牌值=原字面量），提交并跑同状态截图配对，差异应为 0/噪声级；② 若确需改色，另开提交、另做视觉决策与对照记录。

## 验证记录

- [x] 格式化或静态检查：全 QML 写死颜色计数 0；抽查 5 值等值。
- [x] 类型检查或编译：Qt Release 构建通过。
- [x] 单元、集成或端到端测试：CTest 11/11；Web 1296 项。
- [x] 构建：通过。
- [x] 启动或手动回归：qt-qml-load 通过；拆分对照批截图差异在噪声量级。

## 可复用规则

任何「形式重构但声称视觉不变」的改动（令牌化、抽组件、改命名），先做等值替换并证明零视觉差，再谈值调整。适用：有截图/像素配对验收的 UI 工程。例外：无视觉验收手段时，等值替换仍是降低风险的首选，但「零视觉差」只能声明为未验证。

## 适用范围与不适用范围

- 适用：设计令牌收口、组件拆分、样式重构。
- 不适用：功能性视觉变更（本就要改外观的需求）。

## 剩余风险

等值替换不覆盖「令牌被多处共享后某处语义不符」的情况；新增令牌命名需按语义，避免一个令牌承载两种语义导致后续改色互相牵连。
