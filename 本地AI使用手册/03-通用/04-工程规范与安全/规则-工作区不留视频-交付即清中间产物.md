# 规则-工作区不留视频-交付即清中间产物

## 一句话结论

用户规定（m01552/m01560）：`G:\AIrenwu` 工作区不留视频；成品交付确认后删除，渲染/混音中间产物一律落 D 盘缓存目录，工作区只留小体积图/文证据。

## 触发条件与影响

任何视频剪辑/渲染任务的产物落点与收尾清理。违反后果：工作区膨胀（本轮曾积 ~2GB 中间 mp4/wav）、归档时会话目录臃肿、成品重复留存。

## 复现步骤（本轮清理实例）

1. 盘点：glob 工作区 `**/*.{mp4,wav,m4a,mp3,zip}` + Get-ChildItem D 盘任务目录体积清单。
2. 删除（删前核对清单）：工作区 review\seg00–11.mp4、fin_seg00–10.mp4、video_only/review_full/final_video.mp4、narr_track/bgm_track/mix/mix_final.wav、04_产物\平凡的一天_final.mp4；D 盘 vibeclip 仓库+zip（158MB）、不完整 vosk-model-cn-0.22.zip（365MB）、backup_draft_v2/v3、被取代的 narr_orig_16k/wechat_end_clip/wechat_narr.wav。共 37 文件+3 目录 ≈1996.8MB。
3. 脚本改落点防复发：export_final.py OUT=D:\AI-Tool-State\vlog-mint\输出、MEDIA=…\export-cache；review_render.py MEDIA=…\review-cache（REV 只写 jpg/ass/srt）。
4. 复核：工作区媒体残留=0；review 只剩 jpg/png/ass/srt。

## 证据

- 清理前后清单见本轮会话（m01552 起）；删后 glob 工作区媒体=空。
- 脚本落点改动：03_工具脚本\export_final.py:14-19、review_render.py:9-13。

## 根因分析

此前导出/审查脚本把缓存与成品写进工作区证据目录（图/视频混放），无收尾清理纪律。

## 最小修复

落点改 D 盘 + 交付后清理 + 本规则成文（全局记忆 rule-workspace-no-videos.md 同步）。

## 验证记录

- [x] 工作区 mp4/wav/m4a/mp3/zip 残留=0（glob 复核）。
- [x] 释放 ≈2.0GB；CapCut 草稿依赖媒体（origins/graded/bgm/narr_orig.m4a）保留未动。
- [x] 两脚本改落点后语法/路径自洽（MEDIA/OUT mkdir；subtitles 相对路径 cwd=REV 不变）。

## 可复用规则

1. 视频任务开工即定落点：成品 D:\AI-Tool-State\<任务>\输出、缓存 …\*-cache；工作区证据只图/文。
2. 交付经用户确认（「满意/OK」）后清成品+缓存；归档会话前必清。
3. **草稿依赖例外**：CapCut/剪映草稿引用的源媒体备份不可删（删=草稿丢媒体）；清理前列依赖清单。
4. 不完整下载包、被取代的备份/转码中间件=垃圾；完整模型 zip 归 D:\Models\_archives 不算垃圾。

## 适用范围与不适用范围

适用：G:\AIrenwu 工作区一切任务产物。不适用：D:\AI-Tool-State 内的草稿依赖媒体与模型（另有规则）；用户自有文件（H/E 盘原片、微信目录）不动。

## 剩余风险

export-cache/review-cache 今后会再积缓存——下次交付确认后按本规则再清；草稿若被用户删除，其依赖媒体方可清。
