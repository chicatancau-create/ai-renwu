# 规则：技能库做云备份前必须逐条取证许可，7 个技能永不上远端

## 一句话结论

`D:\Skills` 与 `D:\QoderToolkit` 做 git 备份时，**7 个技能被排除在远端之外**：
`docx / pdf / pptx / xlsx`（Anthropic 专有，明文禁止在 Services 外保留副本与转移第三方）、
`reverse-trace / reverse-wechat-miniapp`（无 LICENSE，PROVENANCE 限本机自用）、
`webapp-building`（泄露内容，无任何使用许可）；QoderToolkit 另排除 `web-kimi`。
**私有仓库不能解决这个问题**——上传到托管平台本身就是「转移给第三方」。

## 触发条件与影响

- 触发：用户要求「把技能库推送到 GitHub 和另一个 git 各建一个仓库备份」。
- 影响：若不排除，等于把专有/泄露内容上传到第三方平台，违反随包许可条款。
- 本地照常可用，只是不进远端；恢复时这 7 个要另想办法（本机原件 + 回收站 + 镜像）。

## 可复用规则

1. **上传任何技能/资料库前，先逐个取证许可**：读随包 LICENSE 正文、frontmatter 的 `license`/`homepage`、
   `PROVENANCE.md`、市场元数据。**「没有 LICENSE」不等于「可以自由分发」**，默认按不可分发处理。
2. **「私有仓库」不是豁免理由**。禁止「转移给第三方」的条款，上传到托管平台即触发，与可见性无关。
3. **同一份内容在库里的多个副本要一起判**：用逐文件 sha256 找出同源副本，
   别让「丢了限制条款的那一份」漏网（本机 webapp-building 就是这样漏的）。
4. 排除要**双层**：`.gitignore` + 提交前暂存路径检查。只靠 `.gitignore` 会被 `add -f` 绕过。
5. **密钥扫描的命中必须逐条打开看**，测试夹具里的字符串拼接会大量误报；
   反过来，**审计脚本自己不要把真 key 打印出来**（本机第一版审计脚本会明文回显 claude 的 API key，已改脱敏）。
6. 不伪造署名：`impeccable` 的 frontmatter 写「See NOTICE.md for attribution」但**包内没有 NOTICE.md**，
   登记表里如实记这个瑕疵，不自己编一份。

## 适用范围与不适用范围

- 适用：把本机技能库/资料库推到任何第三方托管平台（GitHub/GitCode/AtomGit/Gitee）。
- 不适用：纯本机自建内容（本机 25 个自建技能可自由备份）。

## 剩余风险

  它们来自 WorkBuddy 市场 / OpenClaw 预装，来源已记在 `THIRD_PARTY.md`。
