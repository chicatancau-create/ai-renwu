# 问题：把仓库从私有改公开，工作区扫干净了不等于安全——历史、代码默认值、证据哈希三处都会翻车

> 事发 2026-11-13，2026-11-15 回写。

## 一句话结论

公开是**不可逆**动作（他人可 fork/克隆，改回私有也收不回）。脱敏要过四道关：
① 扫**全历史**而不只工作区；② 只改文档与证据，**别改代码里的默认值**（会让脚本不可用）；
③ 改了受哈希清单保护的证据，**必须用官方工具重签**，否则门禁红；
④ 历史留痕清不掉时**必须让用户决定**，不能自己替他拍板。

## 触发条件与影响

- 项目或功能：把一个长期私有、含本机取证产物的学习/工程仓库转为 public
- 环境与版本：Windows；git；`gh` CLI 已认证；仓库内有 manifest 哈希清单机制
- 触发条件：执行 `gh repo edit --visibility public`
- 影响范围：全部历史提交对外可见；本机路径、OS 用户名、临时公网隧道 URL 都会暴露

## 复现步骤

1. 前置条件：仓库私有，历史里含本机绝对路径与 `C:\Users\<用户名>\...`
2. 操作或命令：只扫工作区 → 替换 → 直接公开
3. 预期结果：干净且门禁仍绿
4. 实际结果：历史仍可查到旧路径；门禁因证据哈希变化而红；脚本默认值被改坏

## 证据

**① 工作区 vs 全历史（实测）**：

```
工作区硬密钥扫描（ghp_/github_pat_/sk-/AKIA/PRIVATE KEY）：0 命中
全历史扫描：git grep -I -nE '<同上>' $(git rev-list --all)   → 343 个提交，0 命中
但路径类：工作区 188 处 / 62 文件；历史中含 Users\<用户名> 的提交 6 个、含本机盘符路径的 14 个
```

**② 改代码默认值的后果（实测，我自己踩的）**：

```js
// 脱敏脚本把脚本里的默认值也替换了：
const ZAP_HOME = process.env.ZAP_HOME || '<ZAP_HOME>';   // ← 脚本直接不可用
// 还原后：
const ZAP_HOME = process.env.ZAP_HOME || 'D:/ZAP/ZAP_2.17.0';
```

该路径**不含个人身份信息**，且是可复现实验的运行时依赖，本就不该改。

**③ 证据哈希清单（实测两轮）**：

```
改 2 个 heapsnapshot 后：verify_all 20/21
  FAIL manifest E06: HASH MISMATCH evidence/heap/leaked.heapsnapshot
再批量改 39 个证据文件后：verify_all 17/21
  FAIL E03 / E05 / E06 / E11
用官方工具重签 4 份 manifest 后：verify_all 21/21
```

**④ 判「是否受保护」时我查错了位置（实测教训）**：
先按「文件同级目录有没有 manifest.json」判，得出 heapsnapshot「无 manifest」；
实际清单在**上一级** `evidence/manifest.json`，其 `artifacts[].path` 写的是
`evidence/heap/leaked.heapsnapshot`。⇒ 判保护关系要**向上找清单并比对完整相对路径**。

**⑤ 公开生效判据（实测）**：

```
gh repo edit --visibility public --accept-visibility-change-consequences  → 无输出（不是失败）
gh repo view --json visibility,isPrivate → {"visibility":"PUBLIC","isPrivate":false}
匿名 curl https://api.github.com/repos/<o>/<r> → 200（这才是对外可读的证据）
```

**⑥ 提交信息与测试夹具是两处最容易漏的载体（2026-11-15 第二次实例，实测）**：

```
推私有存档仓库前的三查：
  git status + git ls-files            → 登录态目录/原始报文/库文件均 gitignore，未跟踪 0 处
  git log --all --format='%B' | grep  → 命中 2 条**提交信息**带第三方对象名（工作树里根本没有）
  git grep -I <标识符> <分支>          → 命中 1 处**测试夹具硬编码真实 ID**（19 位会话标识）
处置：夹具换成同形状的合成值（长度/字符类不变，断言仍有效）→ 单独提交；
      提交信息用 git filter-branch -f --msg-filter '<脚本做替换>' -- --all 重写，
      然后必须删 refs/original/*（filter-branch 会留备份引用，不删等于历史还在原处）；
      复验：git log --all 与 git grep on main 双向 0 命中后才推。
推完核对远端：git fetch <remote> && rev-list --count 两侧相等 && ls-remote SHA 一致。
```

顺带一条同源坑：批量核对文件名时用 `git ls-files` 默认输出会把非 ASCII 路径八进制转义，
造成「一个都没匹配上」的假结论，必须 `-z` 按字节比。

## 根因分析

- 已确认的根因：
  1. 私有→公开是**披露范围一次性扩大**，历史对象一并可见，工作区干净不构成安全结论。
  2. 脱敏脚本按「文件里出现路径就替换」执行，未区分**文档/证据**与**可执行代码**。
  3. 证据产物被哈希清单锁定，内容一改哈希即失配。
- 排除过的假设：
  - 不是密钥泄露：全历史扫描 0 命中；命中的 `password: 'alice-pass'`、
    `postgresql://p02:p02-ci-pass@127.0.0.1` 都是**测试夹具/CI 本地库**，非真实凭据。
  - 不是第三方资料侵权：镜像正文已被 `.gitignore` 排除，入库的只有 11 个元数据文件（1.1 MB）。
- 问题归属：本次操作引入（脱敏范围与判定方式），不是仓库原有缺陷。

## 最小修复

**公开前检查清单（按顺序）**：

1. 扫**全历史**硬密钥与私钥：
   ```bash
   git grep -I -nE '(ghp_[A-Za-z0-9]{20,}|github_pat_[A-Za-z0-9_]{20,}|sk-[A-Za-z0-9]{24,}|AKIA[0-9A-Z]{16}|-----BEGIN [A-Z ]*PRIVATE KEY-----)' $(git rev-list --all)
   ```
2. 扫个人标识：`Users\<用户名>`、手机号、身份证、真实姓名、邮箱；
   区分**真实凭据**与**测试夹具**（后者可保留）。
   2b. 扫**提交信息**与**夹具里的硬编码标识符**（对象名/会话 ID/账号 ID 类）：
       这两处不在工作树文本里，只扫文件会漏；改法见证据 ⑥。
3. 确认第三方镜像正文未入库（查 `.gitignore` 与 `git ls-files` 体积）。
4. 脱敏**只改文档与证据**，替换为 `<资料库根>` / `<练习仓库>` / `<临时目录>` 这类占位符；
   **代码默认值不动**（改了要还原）。
5. 找出受哈希清单保护的产物：**向上找 manifest**，比对 `artifacts[].path` 完整相对路径；
   改完用官方工具重签（保留原 artifacts 列表与 commands 记录）：
   ```bash
   node ../_template/manifest.mjs make --experiment <ID> \
     --output evidence/manifest.json --files=<原清单路径,逗号分隔> \
     --command="<原 cmd>|<原 exit>"
   ```
6. 跑全仓门禁 + 文档链接校验，确认回到全绿。
7. **历史仍留痕时，把选项和代价摆给用户**：直接公开 vs `git filter-repo` 重写历史 + 强推
   （后者改变所有 commit hash，协作方需重新克隆）。用户拍板后才执行。
8. 公开后**用匿名请求核验**，并检查默认分支指向的内容是不是最新
   （本轮默认分支落后主线 101 个提交，需另行快进合并）。

## 可复用规则

1. **公开/开源前扫全历史**，`git grep $(git rev-list --all)` 是最低成本做法；
   只扫工作区会漏掉已删除但仍在历史里的敏感文件。
2. **脱敏范围要分类**：文档、证据可改；**可执行代码的默认值不改**——
   把默认路径换成占位符等于把脚本改坏，而且这类路径通常不含隐私。
3. **改受哈希清单保护的产物必须重签**；判保护关系要向上找清单、比完整相对路径，
   不能只看文件同级目录。
4. **不可逆披露动作必须用户拍板**：把「清不掉的残留 + 两种方案的代价」讲清楚再执行，
   不要自己决定重写历史或忽略残留。
5. 公开生效的判据是**匿名请求能读到**，不是命令返回 0；
   同时要检查**默认分支**是否指向最新内容，否则访客看到的是旧版本。

## 适用范围与不适用范围

- 适用：含本机取证产物、manifest 哈希清单、长期私有历史的仓库转公开
- 不适用：已公开仓库的增量提交（无披露范围变化）；不含证据哈希机制的仓库可跳过第 5 步

## 剩余风险

- 历史里的本机路径与 OS 用户名**仍可见**（用户已知情选择保留）；
  若日后要彻底清除，需 `git filter-repo` + 强推三端，且所有克隆需重建。
- 本轮未验证「公开后 Actions 额度行为」，相关结论见关联记录。
- 临时公网隧道 URL（`*.trycloudflare.com`）留在历史证据里；此类 URL 通常已失效，
  但**未逐个实测其存活状态**。
