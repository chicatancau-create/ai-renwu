# 提示词接入规范

将以下内容加入 Codex 的长期提示词或项目级提示词中：

```text
工程知识库位置：D:\Codex\Engineering-Knowledge

执行任何工程任务前：
1. 读取 D:\Codex\Engineering-Knowledge\README.md。
2. 读取 D:\Codex\Engineering-Knowledge\01-标准\工程执行标准.md。
3. 需要选择或调用本机工具时，读取 D:\Codex\Engineering-Knowledge\00-入口\本机开发环境.md，并再次以当前命令输出确认状态。
4. 根据当前项目、语言和框架，依次检索 D:\Codex\Engineering-Knowledge\04-项目索引、03-模式库、02-错误复盘 中的相关 Markdown 文件；不要只按文件名猜测，先读取内容。
5. 同时遵守当前仓库的 README、AGENTS.md、贡献指南和现有代码规范；当前任务的明确要求优先于知识库中的一般规则。

完成任务并验证后：
1. 只有可复现、有证据、根因已定位、修复已完成且验证通过的问题，才写入 D:\Codex\Engineering-Knowledge\02-错误复盘；未满足条件的材料只能放入 99-收件箱并标记 needs-review。
2. 使用 D:\Codex\Engineering-Knowledge\90-模板\错误复盘模板.md。
3. 记录现象与证据、根因、最小修复、实际验证命令、预防规则和适用范围。
4. 不记录密码、令牌、API Key、私钥、个人隐私或生产敏感数据；敏感内容必须脱敏。
5. 单次事件不要直接升级为通用标准；只有至少两次独立验证，或一次覆盖多个项目且边界明确的验证，才整理到 03-模式库，并写清适用条件、不适用范围和验证方式。
6. 最终报告必须明确区分已通过、失败、未执行的检查及剩余风险。
```

## 建议的读取顺序

`README.md` → `01-标准/工程执行标准.md` → 相关项目索引 → 相关模式 → 相关错误复盘。

## 重要边界

知识库是辅助记忆和质量保障，不是权限绕过机制；不得用其中内容绕过当前仓库安全规则、用户明确要求或更高优先级系统指令。
