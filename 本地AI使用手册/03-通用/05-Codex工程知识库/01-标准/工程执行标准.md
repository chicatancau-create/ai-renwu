# 工程执行标准

## 规则优先级

从高到低依次为：系统与安全要求、用户当前任务的明确要求、当前仓库的 `AGENTS.md`/贡献指南、项目现有可验证约定、本知识库通用规则、个人偏好。发生冲突时遵守更高优先级，并在最终报告中说明取舍；不能用知识库规则绕过权限、验证或安全边界。

## 开始前

- 阅读当前仓库的 README、AGENTS.md、贡献指南、配置与相关实现。
- 检查 Git 状态，保护用户已有修改。
- 确认包管理器、锁文件以及真实的构建、测试、Lint、格式化和类型检查命令。
- 阅读相邻的 2～3 个同类文件，遵循现有风格。
- 明确任务范围、入口、调用链、数据流、外部服务和不可改变的约束。
- 先区分修改前已有的问题、当前任务可能引入的问题和环境/外部依赖问题；没有证据时不要下结论。
- 参考 [[任务开始检查清单|任务开始检查清单]]，按项目实际能力勾选，不虚构不存在的命令。

## 实施中

- 做完成需求所需的最小合理改动，不顺手重构无关代码。
- 优先复用已有能力；新增依赖前说明必要性。
- 处理输入、空值、失败、并发、权限和兼容性边界。
- 不写入秘密，不绕过校验，不用忽略规则掩盖错误。
- 保持相邻代码的命名、缩进、导入顺序、错误处理和 API 返回结构一致。
- 对新行为补充正常、失败和关键边界测试；修复 Bug 时先保留可复现证据，再确认回归测试由失败变为通过。

## 完成前

- 依项目能力执行格式、Lint、类型、测试、构建和运行验证。
- 独立复查需求、代码、可靠性、安全性和验证证据。
- 明确区分通过、失败、未执行及剩余风险。
- 参考 [[修改后验证清单|修改后验证清单]]，只报告实际执行的命令和结果。
- 仅将经过验证、可跨任务复用的教训写回本库；具体问题按 [[../90-模板/错误复盘模板|错误复盘模板]] 记录。
