# Codex 工程知识库

这是 Codex 的长期工程复盘、执行标准和项目入口库。内容使用 UTF-8 纯 Markdown 保存，不依赖 Obsidian 才能读取；Obsidian 只是浏览和编辑界面。

## 目标与边界

- 目标是帮助 Codex 在真实项目中保持一致的分析、实现、验证和复盘流程。
- 知识库是辅助记忆，不是权限绕过机制，也不替代当前任务、仓库 `AGENTS.md`、安全策略或用户明确要求。
- 不创建虚假的项目、错误、测试结果或验证结论；缺少证据时明确标记为未验证。

## 每次任务的读取顺序

1. 读取本文件和 `01-标准/工程执行标准.md`。
2. 按当前项目名、语言、框架、工具和错误关键词检索 `04-项目索引/`、`03-模式库/`、`02-错误复盘/`。
3. 读取命中的正文，不能只根据文件名或标题判断适用性。
4. 以当前任务明确要求、系统/安全规则、仓库 `AGENTS.md` 和项目现有约定为更高优先级；冲突处理见 `01-标准/规则冲突与优先级.md`。
5. 按 `01-标准/任务开始检查清单.md` 开始工作，完成后按 `01-标准/修改后验证清单.md` 回归。

## 检索方式

- 优先搜索项目名、仓库目录、语言、框架、包管理器、命令、错误信息中的稳定关键词。
- 使用 `01-标准/知识库检索关键词规范.md` 组合 2～4 个关键词，再读取候选文件全文。
- 优先看 `04-项目索引` 了解入口和命令，再看 `03-模式库` 的适用条件，最后看 `02-错误复盘` 的具体证据。

## 写入与升级原则

- 错误复盘只有在问题可复现、根因已定位、修复已完成且验证通过后才能进入 `02-错误复盘`。
- 每条复盘必须区分原有问题、本次修改引入的问题和环境/外部依赖问题；无法区分时保留不确定性，不武断归因。
- 单次事件不能直接升级为通用模式；只有至少两次独立验证，或一次覆盖多个项目且边界明确的验证，并记录适用条件、不适用范围和验证方式，才进入 `03-模式库`。
- 项目入口信息放在 `04-项目索引`，使用项目索引模板；不得把凭据或未验证命令写成事实。
- 规则变化应通过新增或明确标记 `deprecated` 的记录完成；不要静默改写历史证据。

## 安全与隐私

- 严禁保存密码、Token/令牌、API Key、私钥、Cookie、连接字符串、个人隐私和生产敏感数据。
- 日志、路径和配置中的敏感值必须替换为占位符，例如 `<REDACTED>`、`<PROJECT_ROOT>`；具体要求见 `01-标准/敏感信息与脱敏规则.md`。

## 目录职责

| 目录 | 只放什么 |
| --- | --- |
| `00-入口` | 首页、提示词接入和导航 |
| `01-标准` | 通用、可执行的工程规则与检查清单 |
| `02-错误复盘` | 已复现、已定位、已修复、已验证的具体问题 |
| `03-模式库` | 经过多次验证且有边界的可复用方法 |
| `04-项目索引` | 项目路径、技术栈、命令、约束和历史链接 |
| `90-模板` | 新记录使用的最小模板 |
| `99-收件箱` | 尚未验证或待整理的临时材料；不能当作规则使用 |
