# 踩坑：计划任务 action 写裸命令名报 0x80070002——本机根本没有 pwsh

> verified 2026-11-15。severity medium（一次性清理任务空转 12 小时无人发现）。

## 症状

一次性任务 `DSH-debuglog-cleanup`（停客户端→删 debug.log→重启客户端→自删）注册后准点触发：
`Get-ScheduledTaskInfo` 的 LastRunTime=01:47:58 与触发时刻一致，但 **LastTaskResult=2147942402 = 0x80070002（ERROR_FILE_NOT_FOUND）**。
脚本一行没跑 ⇒ 脚本里的自删没执行 ⇒ 任务残留 Ready，占用文件原封不动。

## 根因（实测，不是环境差异）

- action 写的是 `Execute='pwsh'`。本机 **PowerShell 7 未安装**（`C:\Program Files\PowerShell\7\pwsh.exe` 不存在），PATH 里也没有任何 pwsh——agent shell 里 `Get-Command pwsh` 同样 CommandNotFoundException。
- agent 的「pwsh」工具实际引擎是 **Windows PowerShell 5.1**（`$PSVersionTable` = 5.1.28000.3365 Desktop，`C:\WINDOWS\System32\WindowsPowerShell\v1.0\powershell.exe`）。**工具名 ≠ 可执行文件名**。
- 所以裸 `pwsh` 在任何上下文都解析不到。最初以为「agent shell 能解析、任务环境不能」是错的：两边都不能。

## 规则

1. 计划任务 action 一律写**全路径**：`C:\WINDOWS\System32\WindowsPowerShell\v1.0\powershell.exe`（或实测存在的 pwsh 全路径）。注册前 `Get-Command` / `Test-Path` 验证可执行文件真的存在。
2. **注册 ≠ 会跑**：事后必查 `Get-ScheduledTaskInfo` 的 LastRunTime / LastTaskResult；0x80070002 = 可执行文件没找到，不是脚本逻辑错。
3. `Register-ScheduledTask` 默认 Settings 实测读回：`DisallowStartIfOnBatteries=True`、`StopIfGoingOnBatteries=True`、`StartWhenAvailable=False`。笔记本上的一次性任务要显式 `New-ScheduledTaskSettingsSet -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries -StartWhenAvailable`，否则电池供电或错过触发就静默空转。
4. 「停宿主→删占用文件→重启宿主」不能放在 agent 会话内跑（Start-Process 子进程随工具会话结束被连带回收，见 [[踩坑-执行环境Start-Process子进程在工具会话结束时被连带回收]]）；独立计划任务是正确载体，但按 1–3 落。
5. **占用不是永久的**：宿主重启后新实例未必再占用（本次次日客户端重启后 debug.log 直接 `Remove-Item` 成功）。强停宿主之前，先试一次直接删。

## 收尾

debug.log 手动删除；残留任务 `Unregister-ScheduledTask` 注销。
执行脚本留存 `G:\AIrenwu\01_任务归档\2026-11-15_文件夹归类与大纲规矩\03_工具脚本\cleanup_debuglog.ps1`——复用前先把 action 改成全路径并补 Settings。
