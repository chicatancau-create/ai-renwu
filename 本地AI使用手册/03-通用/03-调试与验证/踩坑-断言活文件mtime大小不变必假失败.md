# 问题：测试断言"日志文件 mtime+大小不变"偶发失败，其实什么都没坏

> verified：假失败已复现（55 秒内日志被真实写入者追加 289 字节），改断言层次后转绿且仍能抓住真回归。

## 一句话结论

被测程序在跑的时候，**别的进程正在往同一个日志文件里写**。此时"文件 mtime/大小不变"这个断言测的是"世界上没人写这个文件"，而不是"我没破坏它"。正确写法是断言**运行前已有的那部分内容字节级原样保留**（`新内容.startswith(旧内容)`）。

## 触发条件与影响

- 项目或功能：`watch.py`（常驻窗口监视器）配套的 `doctor.py` 自检，测试 `test_report_does_not_touch_mtime`
- 环境与版本：Windows 11 + 自建测试运行器（无 pytest），程序以计划任务常驻（PID 一直活着）
- 触发条件：常驻进程在测试执行期间向 `watch.log` 追加日志（用户一操作窗口就会写）
- 影响范围：
  - 测试**随机**变红，与被测逻辑无关 → 开始怀疑"是不是我改错了"，浪费大量时间
  - 反过来更危险：为了让它变绿而放宽到"不检查"，就把真回归也放走了

## 复现步骤

1. 前置条件：常驻监视器运行中；`watch.log` 持续被写入
2. 操作：记录 `watch.log` 的 `mtime` 与 `st_size` → 调用 `doctor.py` 的报表函数 → 再读一次
3. 预期结果：（原断言）mtime 与 size 完全相同
4. 实际结果：size 变了。实测 55 秒间隔：`137414 → 137703` 字节

## 证据

```
watch.log  mtime 2026-11-14 20:0x:xx  size 137414
... 55s 后 ...
watch.log  mtime 2026-11-14 20:0x:xx  size 137703
```
同一时刻 `watch.json`（只被读取、不被写入的配置文件）mtime 与 size 稳定不变 —— 说明写入者只有常驻进程，不是被测函数。

## 根因分析

- 已确认的根因：断言对象选错层次。想验证的是"报表函数没有改动文件"，写成了"文件对象的元数据没有变化"。后者是**全局条件**，在有任何其他写入者时必然不成立。
- 排除过的假设：
  - 不是报表函数在写：`watch.json`（同样是它读的文件）元数据纹丝不动；且日志新增内容是监视器正常业务行。
  - 不是文件系统时间精度问题：size 也变了。
- 问题归属：测试自身写错（本次修改引入的坏断言，不是产品 bug）。

## 最小修复

分两类断言，各测各的：

```python
# 1) 只被读、不被写的配置文件：可以严格断言元数据不变
assert (json_mtime, json_size) == (json_mtime_before, json_size_before)

# 2) 活跃日志：断言"既有内容未被改写"（前缀保留），而不是"文件没变"
now = log_path.read_text(encoding="utf-8", errors="replace")
assert now.startswith(before_text)      # 运行前那部分必须字节级还在

# 3) 日志被轮转/清空（变短）时跳过该断言，不算失败
if len(now) < len(before_text):
    skip("日志已轮转")
```

影响面：只改测试，产品代码零改动。

## 可复用规则

1. 写"不破坏"类断言前先问：**这个文件在测试期间还有别人写吗？** 有就换成内容级断言（前缀/哈希/行数不变）。
2. 断言的层次要匹配意图：想证明"我没改"→断言**内容**；想证明"没人碰过"→才断言**元数据**，且仅在独占文件上可用。
3. 看到"偶发失败 + 与被测逻辑无关 + 系统里有常驻进程"三件套，先怀疑断言写错层次，不要先去怀疑代码。
4. 放宽断言时必须保留检出能力：本例用 `startswith` 而不是删掉整个检查。

## 适用范围与不适用范围

- 适用：任何"被测程序与非测试进程共享日志/缓存/数据库文件"的场景（常驻服务、监视器、守护进程、有后台同步的桌面应用）。
- 不适用：测试独占的临时文件、mock 掉的文件系统、以及真正"必须证明只读"的场景（那里应改用文件锁或只读句柄验证）。

## 剩余风险

- `startswith` 断言假定日志只追加不重写；若程序会重排/压缩日志，需要改为"旧内容哈希在多行中存在"这类更强检查。
- 日志轮转期间读取可能拿到半行，需容错解码（`errors="replace"`）避免解码异常掩盖真实断言。
