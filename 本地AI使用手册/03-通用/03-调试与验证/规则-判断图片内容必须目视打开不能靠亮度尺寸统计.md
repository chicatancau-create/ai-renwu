# 问题：凭「平均亮度 34.8、很暗」断定某张图就是用户桌面的星空，实际打开是紫红色光环

> `needs-review` 表示尚未完成验证；只有复现、定位、修复和验证都完成后，才改为 `verified`。

## 一句话结论

统计量只能证伪「有内容 vs 全黑」，**不能证明内容是什么**。要判「这张图是不是我要的那张」，唯一有效动作是把图打开看一眼（多张时拼成一张 montage 一次看完），任何基于尺寸、平均亮度、直方图形状的推断都不许写进结论。

## 触发条件与影响

- 项目或功能：需要确认「磁盘上某个文件是否等于屏幕上看到的东西」的取证任务（壁纸、截图、缓存图、缩略图）。
- 环境与版本：Windows 11，Python 3.14 + Pillow 12.3。
- 触发条件：拿到一个无扩展名的图片文件，先算尺寸/亮度，再据此下判断并继续往下建链路。
- 影响范围：整条后续设计建立在错误前提上，浪费的是一整轮实现；更糟的是错误结论会被写进报告并被用户当作事实。

## 复现步骤

1. 前置条件：桌面显示一张星空壁纸；系统里存在一个「看起来该是它」的图片文件。
2. 操作或命令：`Image.open(p)` 取 size/format，转 L 求 `mean`、`max`。
3. 预期结果（当时的错误预期）：平均亮度 34.8、最大值 247、3840×2400 ⇒「很暗且有亮星点，就是星空」。
4. 实际结果：把同一文件真打开看图，内容是**紫红色光环抽象图**，与桌面星空无关。星空是动态壁纸程序在推，系统层那张是过期快照。

## 证据

- 同一文件两次测量：统计量口径给出的结论 = 「星空」；目视口径 = 「紫红光环」。两者互斥，目视胜。
- 后续为了在多张候选里认出正确的那张，把 3 个动图预览的首帧拼成一张 montage 一次目视比对，才锁定唯一匹配项——这个动作是本次唯一有效的判据来源。

## 根因分析

- 已确认的根因：把「暗 + 有高光」当成星空的**充分**条件；实际它只是星空的必要条件之一，紫红光环同样满足。特征取值时没有构造反例（任何满足统计特征但不是目标物的图都存在）。

## 最小修复

判内容一律走目视：单图直接打开；多图用 PIL 拼 montage（缩略到统一尺寸 + 在图上标候选 id）后一次看完再下结论。统计量只用于「是否为空/全黑/损坏」这类二值判断，并在结论里写清它证明到哪一层。

## 可复用规则

1. 结论里出现「这张图是 X」时，自检一句：我是**看过**它，还是只**量过**它？只有量过就改成「量到的是暗图，内容未证实」。
2. 多候选比对优先做 montage，一次目视胜过多次单图打开。
3. 适用：任何要拿磁盘文件对应屏幕呈现的取证。不适用：像素级一致性校验（那种场景哈希/逐像素比较才是判据，目视反而会漏）。

## 适用范围与不适用范围

- 适用：内容识别、来源核验、候选筛选。
- 不适用：已知内容、只需验完整性的场景。

## 剩余风险
