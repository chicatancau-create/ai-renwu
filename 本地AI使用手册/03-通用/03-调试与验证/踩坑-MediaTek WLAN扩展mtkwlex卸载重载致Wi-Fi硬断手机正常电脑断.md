# 问题：MediaTek WLAN 扩展 mtkwlex 卸载重载致 Wi-Fi 硬断（手机正常电脑断）

## 一句话结论

「手机能用、电脑断」且 Wi-Fi 约 6 秒硬断再重连，查 `WLAN-AutoConfig 10002` + `mtkwlex 1033/8001→8000/1030`，是 MediaTek WLAN 扩展模块（mtkihvx.dll）被卸载重载，属本机驱动层，与节点/运营商无关。

## 触发条件与影响

- 环境：Windows 11，MediaTek Wi-Fi 6E MT7922（驱动 3.6.2.1438），接手机热点。
- 触发：不定时（本例 10:05:47、10:47:43），与重启/代理操作无必然因果。
- 影响：Wi-Fi 硬断约 6s，期间所有连接中断；手机（蜂窝）不受影响。

## 复现步骤

1. 前置：电脑接热点、手机同网正常。
2. 操作：观察断网时刻的系统日志。
3. 预期：找到链路/运营商原因。
4. 实际：`WLAN-AutoConfig 10002 WLAN 扩展模块已停止`（模块 `C:\WINDOWS\system32\mtkihvx.dll`），`mtkwlex` 1033/8001，约 6s 后 8000/1030 重载；同刻 `11004 无线安全已停止`+`8003 断开连接`。

## 证据

- 系统日志 2026-11-11 10:05:47 / 10:47:43 两条 10002 + mtkwlex 序列（incident-events.txt）。
- 手机同网始终正常 → 排除运营商/节点。

## 根因分析

- 已确认：WLAN 扩展模块卸载重载导致硬断（驱动层）。
- 排除：运营商/节点（手机正常）、DNS（硬断是链路层）。
- 归属：环境/驱动。UmiTun 出现与某次掉线时间吻合但非必然因果，不单独归因。

## 最小修复

- 干净重启可让 mtkwlex 重新加载恢复；反复出现则更新 MT7922 驱动。
- 排障顺序：先查本机 WLAN 扩展/驱动与代理状态，再怀疑节点。

## 验证记录

- [x] 日志序列与掉线时刻对齐；重启后恢复（2026-11-11）。

## 可复用规则

- 「手机正常电脑断」先查本机：`WLAN-AutoConfig 10002`+`mtkwlex`（Wi-Fi 硬断）、代理主进程+端口（代理悬空），别先怀疑节点。
- 判 Wi-Fi 硬断看 10002+mtkwlex 重载序列，不是「感觉慢」。

## 适用范围与不适用范围

- 适用：MediaTek MT7922 / 同类带 WLAN 扩展模块的网卡。
- 不适用：无扩展模块的网卡（日志特征不同）。

## 剩余风险

- 驱动更新前仍可能复发；热点 UDP 丢包是另一独立问题（见 DoH 记录）。
