# 问题：PixPin 启动即崩 0xC0000409，根因是截图历史索引目录损坏

> `verified`：复现、定位、修复、验证均完成（2026-11-24）。

## 一句话结论

PixPin 3.6.6.0 每次启动秒退、退出码 `0xC0000409`（STATUS_STACK_BUFFER_OVERRUN / __fastfail），根因是用户数据目录里的截图历史索引 `History\_ScreenshotRecord` 在上一次截图崩溃时被写坏；把该目录改名隔离后即正常启动，截图功能恢复。二进制、系统、GPU 均无问题。

## 触发条件与影响

- 项目或功能：PixPin 截图工具（Qt5 程序，装在 `D:\PixPin`，非 Electron）。
- 环境与版本：PixPin 3.6.6.0；Windows 10.0.28000；RTX 5070 Laptop GPU；2560x1600。用户配置 `System.Run After Boot.RunAsAdmin=True`（开机以管理员身份运行）。
- 触发条件：某次按全局热键 Ctrl+1 截图时，`TrigerGraphicRectSelectItem::initUiRegionDetector` 等待初始 UI 识别结果超时（timeoutMs=1000）后崩溃，崩溃过程写坏了截图历史索引目录。此后每次启动读取该损坏索引即触发 __fastfail。
- 影响范围：PixPin 完全无法启动（启动即退），截图功能不可用。

## 复现步骤

1. 前置条件：`%LOCALAPPDATA%\PixPin\History\_ScreenshotRecord` 已损坏（本例修改时间停在崩溃时刻 18:26:27）。
2. 操作或命令：`Start-Process 'D:\PixPin\PixPin.exe' -PassThru`（直接 / `-Verb RunAs` / explorer 拉起 / 设 `QT_OPENGL=software` 均一样）。
3. 预期结果：PixPin 常驻运行。
4. 实际结果：进程秒退，`ExitCode=-1073740791`（即 `0xC0000409`）；`%LOCALAPPDATA%\PixPin\pixpin.log` 被截断为 0 字节；无 WER 报告（__fastfail 不走 WER）。

## 证据

- 退出码 `-1073740791` = `0xC0000409` STATUS_STACK_BUFFER_OVERRUN（__fastfail，故意快速失败，不产生 WER 转储）。
- `D:\PixPin\PixPinAuxiliary.log`：18:25:59 以 `mode:Elevated` 自我重启成功（说明二进制能跑）。
- `%LOCALAPPDATA%\PixPin\pixpin.log` 真尾段（崩溃前那次）：18:26:22 Ctrl+1 抓屏成功（imageSize 2560x1600 isNull=false）、截图窗建好；最后一行 18:26:23.409 `[warning] [TrigerGraphicRectSelectItem::initUiRegionDetector] Timed out waiting for initial UI detection result, timeoutMs=1000`；此后日志中断。
- Crashpad（`%LOCALAPPDATA%\PixPin\Crashpad`）：reports 空、last_crash=2026-06-23、无新转储；Application 事件日志近 3h 无 Application Error/WER/Application Hang。
- 隔离实验：把整个 `%LOCALAPPDATA%\PixPin` 改名 `.bak2` 后以全新数据启动 → 正常运行（log 正常 PixTrack/PixUpgrade 初始化）⇒ 二进制/系统/GPU 正常，系用户数据损坏。
- 逐文件隔离：候选 `History\_ScreenshotRecord`、`LocalStorage.data`、`Data\PinWindowd.sqlite`、`LoginData.bin3`、`RightMenu\settings.json` 逐个改名 `.off` 启动测试，**第一个 `History\_ScreenshotRecord` 即命中**——移除后正常启动。

## 根因分析

- 已确认的根因：截图时 UI 识别（onnxruntime / UiRegionDetector）初始化超时致崩溃，崩溃过程写坏 `History\_ScreenshotRecord` 索引目录；此后启动读它即 `0xC0000409`。
- 排除过的假设：① GPU/ANGLE 渲染路径——设 `QT_OPENGL=software` 仍崩，排除；② Electron 的 `ELECTRON_RUN_AS_NODE` 继承——PixPin 是 Qt 非 Electron，无关；③ 二进制损坏/系统问题——全新数据能跑，排除。
- 问题归属：环境或依赖（用户数据损坏），非本次修改引入。

## 最小修复

把损坏的索引目录改名隔离（备份保留，不删）：

```
%LOCALAPPDATA%\PixPin\History\_ScreenshotRecord  →  _ScreenshotRecord.off
```

PixPin 启动时重建新索引。用户截图本体（`Data\*.png` / `*.meta`）、`Data\PinWindowd.sqlite`、`Config` 设置全部保留，仅历史索引重置。改名而非删除，可随时回滚。

- [x] 隔离对照：全新数据能跑、原数据崩、仅移除 `History\_ScreenshotRecord` 即能跑，三组对照成立。

## 可复用规则

- Qt/原生程序「启动即退、退出码 `0xC0000409`、日志被截断为 0、无 WER 转储」时，先怀疑**用户数据目录里的运行时状态文件损坏**，而不是二进制或 GPU。判据：把整个用户数据目录改名后全新数据能启动 ⇒ 锁定数据损坏；再逐文件改名隔离定位坏文件（优先怀疑修改时间停在崩溃时刻的那个）。
- `0xC0000409` 是 __fastfail，不走 WER，别因为「没有崩溃转储/事件日志」就排除崩溃。
- 修复优先「改名隔离 + 保留备份」，不要直接删用户数据；截图类工具的历史索引与截图本体通常分离，重置索引不丢图。

## 适用范围与不适用范围

- 适用：PixPin 及类似「历史索引/运行时状态独立于本体」的 Qt/原生桌面工具启动崩溃。
- 不适用：Electron 程序（另查 `ELECTRON_RUN_AS_NODE` 继承、app.asar）；MSIX 包启动失败（另查框架包状态与延迟删除，见收件箱 Codex 条）。

## 剩余风险

- 触发崩溃的 UI 识别超时（UiRegionDetector 1000ms）本身未修，极端情况下再次截图仍可能超时；但本次验证截图已正常。若复发，可考虑在 PixPin 设置里关闭「截图时智能识别 UI 元素」类选项（如有）。
- 历史索引重置后，旧截图的「历史列表」展示可能为空，但图片文件仍在 `Data` 目录。
