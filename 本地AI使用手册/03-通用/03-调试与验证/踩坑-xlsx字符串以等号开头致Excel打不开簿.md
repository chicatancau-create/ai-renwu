# 问题：生成的分盘小标题用 `=== C: ...` 起头，Excel 打开整本簿直接抛 `0x800A03EC`

## 一句话结论

**写进 xlsx 的任何字符串，只要首字符是 `=`（以及 `+` `-` `@`），Excel 都会当公式解析**；
解析失败时不是"这一格显示不出来"，而是 **`Workbooks.Open` 整体失败、报 `0x800A03EC`**，
表现成"文件坏了 / Excel 坏了 / 路径问题"，极易误导排查。生成侧统一加前导单引号即可。

## 触发条件与影响

- 项目或功能：脚本生成存储盘点报表 xlsx（`G:\AIrenwu\01_任务归档\2026-10-19_存储结构盘点`）。
- 环境与版本：Win11 28000 + Python 3.12 + openpyxl **3.1.5** + Excel **16.0**（ProPlus2024Retail，COM 自动化）。
- 触发条件：某个单元格文本 `str.startswith('=')`，例如用作分节标题的 `=== C: 系统（共 30 项）===`。
- 影响范围：**整本工作簿都打不开**，不是只有那一格坏；用户双击打开时会提示修复或直接失败。

## 复现步骤

1. 前置条件：任意 openpyxl 生成的工作簿，其中一格写入 `=== C: 系统 ===`。
2. 操作或命令：
   ```powershell
   $xl = New-Object -ComObject Excel.Application
   try { $wb = $xl.Workbooks.Open($path, 0, $true) } catch { '{0:X8}' -f $_.Exception.HResult }
   ```
3. 预期结果：正常打开。
4. 实际结果：`COMException: 不能取得类 Workbooks 的 Open 属性`，`HResult = 0x800A03EC`。

## 证据

- **排除文件损坏**：同一文件的 `zip` 结构完好（14 个 entry），`openpyxl.load_workbook()` 回读正常、
  6 张表页名称与单元格值全部正确 —— 即"文件合法，Excel 拒绝"。
- **排除路径与 Excel 首次启动**：同目录下由 Excel 自己 `Workbooks.Add()` 新建再 `SaveAs` 的文件**能正常打开**；
  另一份历史 xlsx 也能打开；`ShownFirstRunOptin=1`、`FirstRun=0`，无残留 EXCEL 进程。
- **逐行二分定位**：把该表每一行单独做成"表头+该行"的小表，156 个文件里**恰好 6 个失败**，
  内容正是 6 个以 `===` 开头的分盘小标题；其余 150 行全部通过。
- **反向确认**：把这 6 处改为 `【C: 系统】共 30 项`（去掉前导 `=`）后，整本簿 `Workbooks.Open` 立即成功、识别 6 张表。
- 误导过程（记录以便下次不重走）：先后怀疑过文件 zip 损坏、路径含中文、工作表名含 `①②③`、
  单元格非法控制字符、`workbookProtection` 空标签、Excel 首次运行协议、`print_area`/`fitToPage` 属性，
  均被对照实验逐一排除。

## 根因分析

- 已确认的根因：Excel 打开 xlsx 时会解析单元格的 `t`（类型）与内容；openpyxl 把 Python `str` 写成
  内联字符串，但 **Excel 读取阶段仍会对首字符为 `=`/`+`/`-`/`@` 的内容做公式词法解析**。
  `=== C: 系统 ===` 不是合法公式，解析抛错，整个 workbook 加载失败，COM 侧表现为 `0x800A03EC`。
- 排除过的假设：见"证据"一段（文件完整性、路径、表名、控制字符、保护标记、首次运行、打印属性）。
- 问题归属：本次修改引入（生成侧内容选择）。

## 最小修复

生成器里统一过一道文本消毒，**不依赖调用方自觉**：

```python
def safe(v):
    """以 = + - @ 开头的字符串会被 Excel 当公式；前导单引号强制按文本。"""
    if isinstance(v, str) and v[:1] in ('=', '+', '-', '@'):
        return "'" + v
    return v
```

所有写单元格的入口（`ws.cell(..., value=...)`）都走 `safe()`；同时避免用纯符号串做分节标题，
改用 `【】` 这类中文括号包裹，语义也更清楚。

## 可复用规则

**凡是脚本写 xlsx/CSV 并要交付，先把所有待写字符串过一道"公式前缀"检查。**
判据（按顺序，别跳）：

1. 现象是"Excel 打不开整本簿 / `0x800A03EC`"时，**先查内容，不要先怀疑文件损坏或 Excel 环境**；
2. 用 `openpyxl.load_workbook()` 回读：能回读 ⇒ 文件合法，问题在 Excel 的解析策略；
3. 逐行/逐块拆成最小样本，用 `Workbooks.Open` 二分，比肉眼找快得多；
4. 排查表单：首字符 `=` `+` `-` `@`、非法控制字符、超长字符串、公式引用不存在的表名。

同时保留另一条既有规则：**排版结论只能靠真实渲染出图签字**（见关联记录）。

## 适用范围与不适用范围

- 适用：openpyxl / xlsxwriter / 任何直接写 xlsx 内联字符串的生成器；含用户输入文本的报表。
- 不适用：纯数值表；Excel 交互编辑后再保存的场合（Excel 自己会正确处理）。

## 剩余风险

- 前导单引号是"强制文本"的通用做法，但**单元格会显示为文本且左上角可能有绿色三角提示**，
  若下游要对该格做数值计算需另测。
- 未在 WPS 与旧版 Excel（2010/2013）上验证 `0x800A03EC` 的表现是否一致。
- 本次未测超长字符串（>32767 字符）与公式注入的其它形态。
