# 问题：课件只给了一张 1020×576 的示例截图，要照着它写 uni-app 的 rpx 尺寸

## 一句话结论

截图能给的是**比例**，不是尺寸。可用的定标法：裁出手机模型 → `1rpx = 模型宽(裁图像素) / 750` →
**拿分隔线间距做校准**（模型里 4 行列表的分隔线间距是已知的 CSS `3em`，量出来对得上，比例才算可信）→
再逐个元素换算。改完必须回到 CDP 真实几何复核，不能只凭看图说"差不多"。

## 触发条件与影响

- 项目：`跨平台应用开发/wofule`「新生入学 APP 个人中心」拓展任务，示例图来自课件截图（无源文件、无标注尺寸）。
- 触发条件：想照抄示例图的头像直径、图标大小、文字缩进、按钮宽度。
- 影响：不定标就只能靠目测猜，猜出来的数（比如头像 200rpx）和示例图的 120rpx 差一倍，一眼就不一样。

## 复现步骤

1. 前置：课件截图 1020×576，右侧是被红色圆角框圈住的手机模型截图。
2. 操作：按颜色阈值找红色框 bbox（`r>170 and g<70 and b<70`）。
3. 预期：得到手机模型区域。
4. 实际：
   - **第一版错**：只限制 `x > 宽/2`，把导航栏右上角那个红色「拓展」按钮一起算了进来，bbox 顶到 y=0 附近。
     加 `y > 0.18h` 把导航栏排除后才干净：`708..957 × 103..538`（250×436）。
   - 裁出后放大 6 倍存盘目视（这一步不能省，见关联记录）。
5. 定标：模型宽 = 250 原图 px = 1500 裁图 px（6 倍）⇒ `1rpx = 1500/750 = 2 裁图 px`。

## 证据

**校准（决定性一步）**：模型里 4 行列表有 5 条分隔线，实测 y = 828 / 1022 / 1217 / 1410 / 1602，
间距 ≈ 194 裁图 px = **100.8rpx**；而工程 CSS 写的是 `.entry { height: 3em; line-height: 3em }`
（根字号 16px ⇒ 48px ⇒ 96rpx）。两者对上 ⇒ 定标可信，可以继续换算。

| 元素 | 裁图实测 | 换算 rpx | 采纳值 | 改后 CDP 实测 |
|---|---|---|---|---|
| 头像直径 | 235 px | 122 | 120 | 60 px = 120rpx ✓ |
| 入口图标 ink 宽 | 90 px | 47 | 50（盒子） | 25 px = 50rpx ✓ |
| 文字缩进（模型左边线→文字左边线） | 155 px | 80 | 80 | `padding-left: 40px` = 80rpx ✓ |
| 按钮宽 / 列表宽 | 691 / 690 px | 92% / 92% | 沿用工程里的 90% | 338 = 338 ✓ |
| 姓名与头像间隙 | 161 px | 84 | 40（不照抄，见"剩余风险"） | — |

- 换算用的 ink/分隔线检测：纯 PIL 逐像素扫 1500×2616 全图三遍，实测 **1.85s**，
  本机 **没有 numpy**（`import numpy` → `ModuleNotFoundError`），不需要装。
- 反例（第一次量出来的假结论）：`ink` 判据没排除红色标注框时，"暗内容"检测把 y 120..2415 整段
  算成一整块（因为框的左右两条竖边每行都有暗像素）。加 `not (r>140 and g<90 and b<90)` 才分开。

## 根因分析

- 已确认根因（方法层面）：截图分辨率与设备无关，`rpx` 的定义是"750rpx = 屏宽"，
  所以只能从截图里**已知的 CSS 量**（这里是 `3em` 行高）反推比例，不能按像素目测。
- 排除过的假设：①"按 iPhone 375pt 直接换算"——示例图不一定是 375 宽的设备，且课件截图可能被缩放过；
  ②"用模型高度定标"——模型上下有导航栏/tabbar，行高比屏幕高更可控，所以选分隔线。

## 最小修复（流程）

1. 颜色阈值定位红色标注框，**先按 y 范围排除导航栏里的红色元素**。
2. 裁出模型 → 放大 5~6 倍存盘 → 目视确认结构（几行、有没有图标、按钮颜色）。
3. 定标 `1rpx = 模型宽裁图像素 / 750`。
4. **用已知 CSS 量校准**：列表分隔线间距 ↔ `3em`；对不上就说明定标错了，别往下换算。
5. 换算各元素 → 取整写进 CSS（只改数值，不改写法）。
6. 改完用 CDP 复核：`Emulation.setDeviceMetricsOverride{width:375,height:667,deviceScaleFactor:2,mobile:true}`
   + `getBoundingClientRect` + `getComputedStyle(el,'::before')`，逐项对上表打勾。

## 验证记录

- [x] 校准：分隔线间距 100.8rpx ↔ CSS `3em`(96rpx)，误差 5%，判可信。
- [x] 换算落地：头像 120rpx、图标盒 50rpx、缩进 80rpx、按钮 90%。
- [x] CDP 复核：375×667@2x 下 14 条断言全 PASS（头像正圆 60px、姓名在右侧同一行、四图标真加载、通栏 338px、无 JS 异常）。
- [x] 无残留：取证脚本用 `--remote-debugging-port=0` + 自有 profile，跑完 `taskkill /T` 并回删目录；
      复核时 `Win3_Process` 里命令行含 `myverify` 的 msedge 计数 0。
- [ ] 未覆盖：换一台设备/换 DSR 缩放后是否仍对得上（rpx 本身与设备无关，但未跨设备实测）。

## 可复用规则

1. **截图给比例不给尺寸**；定标必须挂在一个"已知 CSS 量"上（行高、字号、圆角），并用第二个量交叉验证。
2. **优先选分隔线/行间距定标**，别选屏幕高（含导航栏、tabbar、安全区，变量太多）。
3. **按颜色找标注框时，先按 y 排除同色 UI 元素**（课件里红框 + 红按钮是标配组合）。
4. **"暗像素"判据要显式排除标注色**，否则框的竖边会让每一行都被判成"有内容"。
5. **本机没装 numpy**：PIL 逐像素扫全图（1500×2616 ×3 遍）实测 1.85s，够用就别为此装包。
6. **示例图的间距不必全照抄**：本轮姓名与头像的 84rpx 间隙就没抄（改成 40rpx），
   抄不确定的数比留一个合理值更容易被老师问倒。

## 适用范围与不适用范围

- 适用：课件/设计稿截图反推 uni-app rpx、小程序 px、任何"只有一张图"的还原任务。
- 不适用：有 Figma/Sketch 源文件或标注的场景（直接读标注，别用图像反推）。
- 例外：截图被二次压缩过（行高校准会飘），校准对不上时先怀疑图，不要怀疑 CSS。

## 剩余风险

- 定标假设"模型宽 = 750rpx"，若课件截图本身被裁过边（左右缺一点），所有换算会整体偏移；
  本轮靠分隔线校准把误差压到 5% 以内，没有第二种独立量再交叉验证。
