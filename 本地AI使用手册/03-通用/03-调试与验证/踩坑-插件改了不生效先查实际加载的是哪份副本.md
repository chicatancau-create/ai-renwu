# 问题：插件代码改了三轮、日志里版本号纹丝不动，其实一直是旧代码在跑

## 一句话结论

`local-plugins\<插件>\` 是**源目录**，`node_modules\<插件>\` 才是**真正被加载的**。
两者**并不总是同一个目录**——如果 `node_modules` 里是**实体副本**（不是符号链接），
那你在源目录里的每一次修改都只是改了个没人读的备份。
**判据：`(Get-Item <node_modules路径>).LinkType` 返回 `SymbolicLink` 才会跟随源目录；返回空就是独立副本。**

## 触发条件与影响

- 项目或功能：DSH `desktop` profile 的本地插件开发（`local-plugins` → `node_modules`）
- 触发条件：插件是「复制安装」而非「链接安装」
- 影响：**改了不生效，且没有任何报错**。排查方向会全部跑偏——以为是缓存、是热重载、是内核没重启，
  实际只是改错文件。本轮为此白花了数小时。

## 怎么一眼确认（三步，全部是实测判据）

```powershell
# 1. 它是链接还是副本？
$nm = 'C:\Users\Admin\.dsh\profiles\desktop\node_modules\dsh-preset-unlock'
(Get-Item $nm).LinkType      # SymbolicLink = 跟随源目录；空 = 独立副本（改源目录无效！）

# 2. 两份内容是否真的一样？
Get-FileHash "$nm\index.js", 'C:\Users\Admin\.dsh\profiles\desktop\local-plugins\dsh-preset-unlock\index.js' -Algorithm SHA256

# 3. 到底哪份在跑？看版本标记
Get-Content 'C:\Users\Admin\.dsh\preset-unlock.log' -Tail 1
```

本机实测对照，同一个 profile 下两种安装方式并存：

| 插件 | `node_modules` 里的形态 | 改源目录是否生效 |
|---|---|---|
| `@local/dsh-preset-switcher` | `SymbolicLink` → `G:\AIrenwu\02_项目代码\dsh-preset-switcher` | 立即生效 |
| `dsh-preset-unlock` | **实体副本** | **不生效**（本轮踩的坑） |

> **想「把副本换成符号链接」一劳永逸？先试再决定。** 本机实测 `New-Item -ItemType SymbolicLink`
> 在**非管理员**下直接失败：`PermissionDenied ... NewItemSymbolicLinkElevationRequired`。
> 更要注意的是失败的瞬间 `node_modules` 里可能已经被动过 —— 务必先整目录备份，失败后立刻从备份还原
> 并复核哈希与语法，否则会从「改了不生效」升级成「插件直接不加载」。稳妥做法仍是留一个同步脚本。

## 版本标记：让「哪份在跑」变成可证事实

在每个插件里加一行构建标记，并在 `apply()` 时写进日志：

```js
const BUILD = 'v7'

function trace(line) {
  try {
    appendFileSync('C:\\Users\\Admin\\.dsh\\preset-unlock.log',
      `${new Date().toISOString()} ${BUILD} ${line}\n`, 'utf8')
  } catch { /* 写日志失败不影响功能 */ }
}
```

这样每次改完只要看日志最后一行，就知道新代码有没有真的被加载。
**没有版本标记的插件，无法区分「改错了文件」和「改了没生效」——这是本轮最大的时间损失来源。**

## 改完必须同步，别靠记性

源目录 → `node_modules` 的复制用一个脚本固化，并且**脚本自己断言两份一致**，不通过就报错：

```powershell
# sync-unlock.ps1（必须 UTF-8 带 BOM + CRLF，否则 PowerShell 5.1 按 GBK 解码报假语法错）
$src = 'C:\Users\Admin\.dsh\profiles\desktop\local-plugins\dsh-preset-unlock\index.js'
$dst = 'C:\Users\Admin\.dsh\profiles\desktop\node_modules\dsh-preset-unlock\index.js'

Copy-Item $src $dst -Force
$h1 = (Get-FileHash $src -Algorithm SHA256).Hash
$h2 = (Get-FileHash $dst -Algorithm SHA256).Hash
if ($h1 -ne $h2) { throw "同步失败：两份哈希不一致" }
Write-Host "同步成功，两份一致: $h1"
Write-Host ("当前版本: " + (Select-String -Path $dst -Pattern 'const BUILD').Line.Trim())
```

## 补丁还有第二层风险：`pnpm install` 会把 `node_modules` 里的改动整份换掉

即使确认了「改的就是 `node_modules` 里那份」，改动仍然**不是永久的**：
`dsh plugin ... install` / `pnpm install` 会重新解包依赖，把本地补丁静默冲掉。

本机实测（2026-11-12 升级 `dsh-better-sidebar` 0.30.1 → 0.31.1 时同时发生）：

- `node_modules\@zilliz\memsearch-dsh\client.js` 从 33516 字节变回 32882 字节，
  `SHOW_SKILL_DOCK` / `pinToViewport` 等本地标记**全部消失**，且安装过程不报任何错。
- 装完必须同时核对**每个改过的文件**的字节数与标记，而不是只看安装命令的退出码。

固化的做法（与上面的 `sync-*.ps1` 同一套路，只是方向反过来）：

```
profiles\desktop\local-patches\<包名>\...      ← 补丁源（版本受控，随仓库走）
profiles\desktop\sync-<包名>-patches.ps1        ← 复制 + 逐文件断言 SHA256 相等，不等就 throw
```

实测输出形如 `OK  client.js  B9D1B79A4F1ADE27` / `OK  scripts\maintenance-runner.py  37AC387277028F23`。

> **规则：每次 `pnpm install` / `dsh plugin install` 之后，必须跑一次对应的 `sync-*-patches.ps1`。**
> 装的时候不报错，不代表补丁还在。

另外两个顺手的判据：

- `pnpm install` 若报 `[ERR_PNPM_LOCKFILE_CONFIG_MISMATCH] ... "overrides" configuration doesn't match`，
  是因为 `pnpm-workspace.yaml` 的 overrides 已改过而 lockfile 还是旧的 → 加 `--no-frozen-lockfile`。
- 靠 `file:` 依赖从 `local-plugins` 复制安装的插件（本机 `dsh-preset-unlock`）不受影响，install 后哈希仍一致；
  **受影响的是直接装在 `node_modules` 里被就地修改的第三方包。**

## 插件改完不用重启 DSH

`plugin_manager set_plugin enabled:false` 再 `enabled:true` 会**重新 `apply()` 并从磁盘读新代码**，
不需要重启整个 DSH。实测日志从 `v5 OK:` 跳到 `v6 OK:` 只隔了 2 分钟，进程创建时间没变：

```
08:50:49  v5 OK: ...
08:52:20  v6 OK: ...      ← 禁用+启用后，新代码生效
```

> 注意：这个结论只对**宿主插件**成立。客户端插件（`client.js`）走 `window.__ModuleLoader__`，
> 改完刷新页面即可，也不需要重启。

## 踩坑过程中的错误方向（留作警示）

- 「以为是内核没重启」→ 反复重启 DSH，无效（进程创建时间证明代码确实重载了）
- 「以为是浏览器缓存」→ 清缓存，无效
- 「以为是热重载没触发」→ 禁用启用多次，日志版本号纹丝不动 ← **这一条其实是关键线索，当时没抓住**
- 正确方向：**先确认磁盘上被加载的那份文件内容是什么**，再谈生效机制

## 判据纪律

- **不把「我改了源文件」当成「运行的是我改的代码」**。中间可能隔着一层复制。
- 判断某段代码是否生效，只认**运行时可观测的证据**（版本标记日志、`Get-FileHash` 对比），
  不认「文件修改时间变了」——修改时间变了恰恰是最容易骗人的。
- 遇到「改了不生效」，排查顺序：**加载路径 → 文件内容 → 重载机制 → 缓存**。
  倒着查会浪费大量时间。
- 给插件加**版本标记**属于工程卫生，不是可选装饰；没有它，所有「生效了吗」的问题都无法回答。
