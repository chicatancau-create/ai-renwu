# 问题：Read 显示图是缩放版，按显示坐标裁原图必裁错

> 2026-11-15 回写。事件发生在 2026-11-13 的 cc-hud 会话（定位用户红圈标注的悬浮元素）。

## 一句话结论

Read 工具把大图缩放后显示（本次 2559×1600 显示为 2000×1250，×1.28），凭「看到的坐标」去裁原图会裁到完全无关的区域；定位必须先用像素统计扫描，目视只用于最后确认内容。

## 触发条件与影响

- 项目或功能：任何「看截图 → 裁局部放大 → 判断元素归属」的取证流程。
- 环境与版本：Qoder Desktop 的 Read 图片渲染；PIL（任意版本）。
- 触发条件：原图尺寸大于显示尺寸，且操作者用目视坐标直接 `im.crop((x0,y0,x1,y1))`。
- 影响范围：裁出全黑/无关区域 → 误判「元素不存在」或「元素是别的东西」，进而删错功能。

## 复现步骤

1. 前置条件：一张 2559×1600 的桌面截图，Read 显示为 2000×1250。
2. 操作或命令：按显示坐标估 `(1330,1360)-(1800,1450)` 裁「右下角提示条」。
3. 预期结果：裁到提示条文字。
4. 实际结果：裁到纯黑壁纸（两次裁图均空）。改用像素扫描后一次命中：提示条亮文字行集中在 y≈1231–1239。

## 证据

- 目视裁图产物：两块全黑/只有壁纸噪点的 crop（已清理）。
- 扫描命令与输出（venv PIL）：
  `for y in range(1150,1290): cnt = 亮像素数(x∈1450..2050)` → 排序后 top 行 = `[(1234,145),(1239,145),(1236,117),...]`。
- 按扫描结果裁 `(1400,1010)-(2060,1290)` 放大目视：清楚看到「已导出 G:\cc-hud\cc-hud-usage-all.json（345944 B，rev 3）」提示条，归属确认。
- 会话内 Read 返回的尺寸提示原文：`[Image: original 2559x1600, displayed at 2000x1250. Multiply coordinates by 1.28 ...]`。

## 根因分析

- 已确认的根因：显示层做了等比缩放，目视坐标 ≠ 原图像素坐标；且人眼对「小元素在缩放图里的位置」估计误差可达上百像素。
- 排除过的假设：不是截图本身缺元素（扫描证明元素在 y≈1234）；不是 PIL 裁错（同一函数按扫描坐标裁即正确）。
- 问题归属：取证方法缺陷，非项目代码 bug。

## 最小修复

裁图前两步走：
1. `Image.open(p).size` 拿真实尺寸；若 Read 给了 displayed 尺寸，换算系数 = 原宽/显示宽。
2. 用颜色阈值 + 行/列直方图 + 粗网格聚类定位候选 bbox，再按 bbox 外扩 20–40px 裁；最后目视确认内容。

## 可复用规则

- 凡「从截图里找某个小元素」：先像素扫描定位，再裁，再目视。禁止把目视坐标当原图坐标。
- 统计量只用于**定位**，不用于**判内容**；内容结论必须目视（见 [[规则-判断图片内容必须目视打开不能靠亮度尺寸统计]]）。
- 例外：原图与显示尺寸一致（1:1）时目视坐标可直接用，但仍建议外扩边距。

## 适用范围与不适用范围

- 适用：Qoder/任何会缩放显示图片的 Agent 界面 + 本地 PIL 裁图取证。
- 不适用：浏览器 DevTools 里按 CSS 像素定位（那是另一套坐标系，走 DOM rect）。

## 剩余风险

- 阈值选色不当会漏定位（本次橙色阈值第一版就漏了目标，改亮文字直方图才命中）；多候选时拼 montage 一次目视。

## 补充：2026-11-05 第二次命中——记错自己存盘的放大倍数，八个采样探针六个返回空列表

- 场景：uni-app「个人中心」照课件图还原。课件 slide 原图 1020×576，Read 显示成约 1280×761；
  我把手机模型裁出来放大存盘后，**凭显示图上的目测坐标**去采样图标颜色、文字色、按钮色。
- 实际：存盘脚本里写的是 `scale = 6`（1500×2616），我脑子里按 4 倍（1000×1744）估坐标，
  结果 8 个探针里 6 个返回 `[]`（`icon1 个人信息`、`icon2`、`icon4`、`entry text`、`tab home icon`、
  `tab 个人中心 selected` 全空），只有头像和按钮因为块大碰巧命中。
- 假信号很危险：`[]` 看起来像"图里没有这个颜色/元素"，实际是"坐标不在我以为的位置"。
- 修法（一次改对，之后所有量都出自这套检测）：不猜坐标，改成程序检测——
  1. 颜色阈值 + `y > 0.18h` 过滤定位红色标注框 bbox（得到模型 250×436）；
  2. 行直方图找分隔线（`195<r<235` 且中性、单行命中 >400 列）；
  3. ink 分带检测，且**显式排除标注红**（`not (r>140 and g<90 and b<90)`），否则框的竖边会把
     y 120..2415 整段连成一块"有内容"；
  4. 换算一律用 `crop 自身尺寸`（`1rpx = 模型宽/750`），不用显示尺寸。
- 判据补充：**探针返回空列表时，第一动作是回读 `Image.open(path).size` 与自己写下的 scale 对表**，
  不是下"图里没有"的结论。本条与主记录同一根因（显示缩放 ≠ 原图坐标），按命名规范只补证据不另开记录。
