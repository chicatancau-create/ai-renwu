# 规则：关机/休眠前先关系统代理，再退代理软件

## 一句话结论

Windows 的"系统代理"是**全局注册表设置**，与代理软件是否在运行**完全无关**。
代理软件被关掉而 `ProxyEnable` 仍是 1，下次开机会让**所有程序**去连一个不存在的端口，
表现为「能 ping 通、能解析 DNS，但网页打不开」。所以顺序必须是
**先 `ProxyEnable=0`（并通知系统），再退出代理软件**。

## 触发条件与影响

- 项目或功能：任何"关机/休眠时自动关闭代理软件"的自动化（本次为 Clash Verge）。
- 环境与版本：Windows 11 + Clash Verge Rev（`clash-verge.exe` + `verge-mihomo.exe`）；
  本机 `ProxyServer=127.0.0.1:7897`。
- 触发条件：代理软件开启「系统代理」后，被任务计划/脚本/强制结束等方式关闭。
- 影响范围：**整机联网**。所有走 WinINET 的程序（浏览器、Office、多数桌面客户端）全部失效，
  而 `ping`、`nslookup` 仍正常 —— 极易被误判成"网络故障"或"DNS 污染"。

## 复现步骤

1. 前置条件：代理软件开启系统代理，确认注册表
   `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings\ProxyEnable = 1`。
2. 操作：直接结束代理软件进程（不先关代理）。
3. 预期结果：——（这是要避免的错误做法）
4. 实际结果：注册表 `ProxyEnable` 仍为 1、`ProxyServer` 仍指向 `127.0.0.1:7897`；
   代理端口已无人监听 → 所有 HTTP(S) 请求连接被拒。

## 证据

本机实测（2026-11-03）：

```
ProxyEnable   = 1
ProxyServer   = 127.0.0.1:7897
ProxyOverride = localhost;127.*;192.168.*;10.*;...;<local>
```

`ProxyEnable` 是 `HKCU` 下的普通 DWORD，**没有任何进程在维护它** ——
代理软件启动时写 1、正常退出时写 0。被强制结束就没人写回 0。

## 根因分析

- 已确认的根因：系统代理是**持久化的全局配置**，不是"进程内状态"。
  它的生命周期由代理软件主动管理，进程被异常终止时不会回滚。
- 排除过的假设：不是 DNS 问题（`nslookup` 正常）、不是网卡问题（`ping` 通）、
  不是防火墙问题（连接是被**拒绝**而非超时）。
- 问题归属：设计使然，非缺陷。

## 最小修复

在退出代理软件**之前**：

```python
import winreg, ctypes
KEY = r"Software\Microsoft\Windows\CurrentVersion\Internet Settings"

with winreg.OpenKey(winreg.HKEY_CURRENT_USER, KEY, 0,
                    winreg.KEY_READ | winreg.KEY_WRITE) as k:
    winreg.SetValueEx(k, "ProxyEnable", 0, winreg.REG_DWORD, 0)

# 通知系统立即生效，否则已在运行的进程要等下次读注册表
wininet = ctypes.windll.wininet
wininet.InternetSetOptionW(None, 39, None, 0)   # INTERNET_OPTION_SETTINGS_CHANGED
wininet.InternetSetOptionW(None, 37, None, 0)   # INTERNET_OPTION_REFRESH
```

然后再关进程（先温和 `taskkill /IM <name>`，超时再 `/F`）。

**开机侧**：代理软件重新启动时若自身配置仍是"启用系统代理"，会重新写 1，
所以只要保证它能自启即可恢复。**注意**：本次实测发现 Clash Verge 的
`verge.yaml` 里 `enable_auto_launch: true` 虽然为真，但 HKCU Run / HKLM Run /
「启动」文件夹三处**都没有条目**，该开关并未落地 —— 需另行写
`HKCU\...\Run\<名称>` 兜底。

## 可复用规则

**任何"自动关闭代理软件"的脚本，第一行必须先关系统代理。**

1. 顺序固定：`ProxyEnable=0` → `InternetSetOption` 通知 → 关进程。
2. 关机场景不要只靠事件触发计划任务（可能来不及跑），
   用**常驻进程的隐藏顶层窗口**收 `WM_QUERYENDSESSION` 最可靠
   （消息只窗口 `HWND_MESSAGE` 收不到广播，必须是顶层窗口）。
3. 休眠用 `WM_POWERBROADCAST` + `PBT_APMSUSPEND`；唤醒用 `PBT_APMRESUMEAUTOMATIC`
   决定是否重启代理软件。
4. 动作要在 WndProc 里**同步**做完（约 2 秒内），否则会拖慢关机。

## 适用范围与不适用范围

- 适用：Windows 上所有"系统代理"型工具（Clash / v2rayN / Shadowsocks 等）。
- 不适用：**TUN / 虚拟网卡模式**。该模式下流量走虚拟网卡，不依赖 `ProxyEnable`，
  关掉代理软件后通常是"网卡消失"而不是"代理指向死端口"，故障表现不同。
  另：PAC（`AutoConfigURL`）模式需清该值，而非 `ProxyEnable`。

## 剩余风险

- `clash-verge-service.exe`（LocalSystem 服务）持有 `verge-mihomo.exe` 内核，
  只关 GUI 不会停内核。但本规则的核心目的（不让系统代理指向死端口）在第一步已达成。
- 若代理软件在退出时**自己**又写回 `ProxyEnable=1`，需在关进程后再校验一次。
