# 经验：装不上的 ASR 依赖不要反复试，换 vosk 小模型这条确定性路径

> `verified`：四个课程合计 565 集视频实际转写完成，产物与集数逐一对账。
> 本文只记管线与判据，不含任何课程内容。

## 一句话结论

本机 `faster-whisper` 三条安装路径全部失败（PyPI 解析失败 / 连接重置 / `ctranslate2` 轮子写盘被拒），
**同一动作失败两次就换实现**，改 `vosk-model-small-cn-0.22` + `imageio-ffmpeg`（自带 ffmpeg，不依赖系统安装）后一次跑通，
实测约 **6 倍速实时**；批量转写必须「单集失败记录后继续」，否则一集坏音频会毁掉整批。

## 触发条件与影响

- 项目或功能：把无字幕的课程录播（mp4/avi 等）批量转成逐字稿，作为知识库的证据层。
- 环境与版本：Windows；Python 3.x；无系统 ffmpeg；`pip` 走公网 PyPI 或镜像源。
- 触发条件：视频没有字幕轨，只能靠语音识别；批处理规模上百集。
- 影响范围：装依赖失败会卡住整条任务；单集失败若不隔离，会让几百集的批处理中途停摆。

## 复现步骤

1. 前置条件：`pip install faster-whisper`。
2. 实际结果（三条路径各自失败，报错性质不同）：
   - 直连 PyPI：`getaddrinfo failed`（DNS 层）
   - 换时间点重试：连接被重置 `10054`
   - 下到 `ctranslate2*.whl` 阶段：`WinError 32`（文件被占用/写盘被拒）
   - 换清华镜像源：仍失败
3. 换实现：装 `vosk` + `vosk-model-small-cn-0.22`（约 42 MB）+ `imageio-ffmpeg`。
4. 音频抽取不依赖系统 ffmpeg：

```python
import imageio_ffmpeg
ffmpeg = imageio_ffmpeg.get_ffmpeg_exe()   # 自带二进制，直接可用
```

5. 逐集识别后按集号落一个 `.md`，写完追加进 `_done.txt`。
6. 实际结果：Linux 151 集 / Python 168 集 / HTML+CSS 199 集 / 鸿蒙 47 集，合计 **565 集**产出逐字稿，整体约 6 倍速实时。

## 证据

- 失败面：`faster-whisper` 三条路径的报错分别落在 DNS、传输层、文件系统层，**不是同一个故障换文案**，因此不是"多试几次就好"。
- 成功面：`vosk-model-small-cn-0.22` 解包后本地加载，`imageio_ffmpeg.get_ffmpeg_exe()` 返回可用 ffmpeg 路径，抽取波形正常。
- 吞吐：约 6 倍速实时（1 小时视频约 10 分钟转完），500+ 集仍需数小时，只能分批后台跑。
- 失败隔离：Linux 第 137 集（webmin 安装）报 `Failed to process waveform`，单集跳过，其余 151 集不受影响。
- 对账：四个目录的 `.md` 份数与集数逐一核对，缺集只有上述 1 集。

## 根因分析

- 已确认的事实：
  1. `ctranslate2` 是 `faster-whisper` 的必需二进制依赖，`WinError 32` 属于**目标文件被占用或写入被拒**，不是网络问题；这类失败在同一台机器上重试同一命令不会自愈。
  2. 系统没有 ffmpeg，但 `imageio-ffmpeg` 会把 ffmpeg 二进制打包进 wheel，**天然规避"必须先装系统级 ffmpeg"的前置**。
- 排除过的假设：换镜像源能修 `WinError 32`（不能，那是文件层）；降低并发能修 DNS 失败（不能，与并发无关）。
- 问题归属：环境与依赖（本机网络 + 文件占用），不是代码逻辑。

## 最小修复（可复用管线）

1. **失败两次就换实现**，不在同一条失败路径上加试第三次；记录每条路径的**报错性质**（DNS / 传输 / 文件），性质不同即证明不是瞬时抖动。
2. 中文语音优先 `vosk-model-small-cn-0.22`（小模型、CPU 可跑、约 42 MB）；追求准确率再上大模型，但先确认能装上。
3. **ffmpeg 一律由 `imageio-ffmpeg` 提供**，不假设系统有 ffmpeg、不写死路径。
4. **单集失败不中断整批**：捕获单集异常 → 记入失败清单 → 继续下一集；跑完再统一处理失败清单。
5. **`_done.txt` 断点续跑**：每集成功落盘后才追加，重启时跳过已完成集，长任务必须这么设计。
6. **逐字稿保留原貌**：机器 ASR 有大量同音错字，本层定位是"证据"，不是"知识"；不做机械润色，改写成最新技术栈会破坏与视频的时间对应关系。

## 可复用规则

1. **同一个安装错误连试两次都失败，就换包、换实现，别换镜像源继续试**；先看报错落在哪一层（DNS / 传输 / 文件）。
2. **任何需要 ffmpeg 的批处理，先试 `imageio-ffmpeg`**，能省掉"装系统 ffmpeg + 配 PATH"整条前置。
3. **批量任务里，单个单元的失败必须被隔离并记账**，"跑完"要输出去重后的失败清单。
4. **长任务必须有断点续跑清单**，且清单只在该单元真正落盘后追加。
5. **机器逐字稿不可直接当结论**：同音错字多（专有名词、英文术语尤其），引用前要对回原视频或人工笔记。
6. **证据层与知识层分开存**：逐字稿保留原貌，提炼后的结论另存一处，并标注来源集号。

## 适用范围与不适用范围

- 适用：中文普通话课程录播、会议录音的批量转写；无系统 ffmpeg 的机器；需要"几百集跑完且能证明哪几集失败"的场景。
- 不适用：需要高准确率的字幕交付（小模型错字率偏高，应上大模型或人工校对）；多人混说、强噪声环境（小模型分离能力有限）；实时字幕（6 倍速是离线批处理速率）。

## 剩余风险

- 小模型对专有名词、英文术语、口音重的讲师错字明显，**不能作为原文引用**。
- 单集 `Failed to process waveform` 多为音频编码异常（如个别音轨损坏、采样率异常），本轮只跳过未深查。
- 6 倍速是 CPU 单机实测，换机器或换模型会变；500+ 集仍以小时计，需后台跑并防进程被回收。
- 鸿蒙这类课程含大量英文术语（ArkTS/ArkUI/DevEco），错字率高于纯中文课程。
