# 踩坑：等比缩放函数里加了 `min(f, 1.0)`，"该缩的窗口"悄悄没缩

> `verified`：2026-10-19 在 `G:\AIrenwu\01_任务归档\2026-10-10_桌面核心脚本` 的窗口居中项目里
> 复现 → 定位 → 修复 → 单测 + 真实窗口活体验证全部完成。未实测的项在「验证记录」里留 `[` `]`。

## 一句话结论

把"不放大"写成缩放系数上限 `f = min(box/w, box/h, 1.0)` 后，**只要框的一边比原图大，
函数就整体返回原尺寸** —— 于是"宽超出阈值、必须压窄"的窗口被静默放过。
正确做法是**拆成两个语义单一的函数**：`fit_shrink_only`（保住最小值，给"只居中"用）与
`fit_by_box`（严格按框缩放，给"已判定需要缩放"用），"不放大"归调用方的判定管，不塞进缩放函数。

## 触发条件与影响

- 项目或功能：窗口居中的尺寸规则（`target_rect()`）；同样适用于任何"按容器等比缩放"的代码
- 环境与版本：Python 3.14 + ctypes；Win11 28000；工作区 2560×1540
- 触发条件：窗口宽度已超阈值（须压缩），但高度在容器上限内放得下
- 影响范围：该缩的窗口完全不动，用户的"留白"诉求落空；且不报错、不崩溃，**属于静默失效**

## 复现步骤

1. 前置条件：阈值 `shrink_frac=0.5`（半屏 1280）、宽上限 `shrink_to=0.75`（1920）、高上限 `shrink_h_to=0.84`
2. 操作：对 1550×929 的窗口调用缩放函数，框取 (1920, 1293.6)
3. 预期结果：宽度被压到 1920，等比得 1920×1151
4. 实际结果：**原样返回 1550×929**（因为 1920 > 1550，`min()` 取到 1.0）

## 证据

```
force 版 : _fit_ratio_force(1550, 929, 1920, 1293.6) = (1920, 1151)   ← 正确
受限版   : _fit_ratio      (1550, 929, 1920, 1293.6) = (1550, 929)    ← 白不缩
f 的取值 : min(1920/1550=1.2387, 1293.6/929=1.3925, 1.0) = 1.0 → 原样返回
```

## 根因分析

- 已确认的根因：`1.0` 这个上限被当成"实现细节"塞进了缩放函数，但它的**语义是调用方的业务判断**
  （"窗口够小就别动它"）。两种语义耦合后，任何"框够大"都会把"该缩"一起吞掉。
- 排除过的假设：
  - "是窗口还没稳定"→ 否：把同一输入重复喂给函数，结果恒为原尺寸，与时机无关。
  - "是取整/浮点精度"→ 否：`f` 打印出来就是 1.0，是模运算前就短路了。
- 问题归属：**本次修改引入**（新规则重写时把两个语义合并了）。

## 最小修复

拆函数，职责单一：

```python
def fit_shrink_only(w, h, box_w, box_h):      # 只居中档用：允许"不动"
    f = min(box_w / w, box_h / h, 1.0)
    return (w, h) if f >= 1.0 else (round(w * f), round(h * f))

def fit_by_box(w, h, box_w, box_h):           # 已判定要缩放时用：严格按框
    f = min(box_w / w, box_h / h)
    return (round(w * f), round(h * f))
```

调用方先判定"要不要缩"，再决定调哪个；"不放大"由判定承担，不进缩放函数。
不影响配置项与外部接口。

## 可复用规则

1. 函数名里出现"min/max + 业务阈值"时，先问：**这个阈值是算法本身，还是调用方的判断？**
   是后者就放到调用方。
2. 一个函数只回答一个问题：`fit_shrink_only` 回答"能不能不动"，`fit_by_box` 回答"该多大"。
3. 判据：若"框比原图大"时函数返回原尺寸，而调用方其实要求压缩，就是本坑。

## 适用范围与不适用范围

- 适用：任何"按容器等比缩放"的实现（图片适配、视频缩放、窗口尺寸、布局计算）。
- 不适用：算法级的数值饱和（如定点数溢出保护）——那是算法本身，应在函数内。

## 剩余风险

拆函数后若调用方漏了"不放大"判断，仍可能把窗口放大；本项目的补偿是缩放档**不设额外面积兜底**
（等比压窄会把高度带大，如 1550×929 → 1920×1151，这是"填满可放区域"的正常结果），
所以"不放大"只在"只居中"档成立，需在文档里写清。
