# 问题：装了国内版和国际版两个 Qoder，记忆是不是共用一份

> 本条已完成实测、迁移、校验三步，状态 `verified`。

## 一句话结论

**完全独立，不通用**：国际版在 `C:\Users\Admin\.qoder`，国内版在 `C:\Users\Admin\.qoder-cn`，两边 `settings.json` 里没有任何指向对方的配置，也没有 junction/软链。项目 slug 命名规则一致（都叫 `G--AIrenwu`），所以**格式相同、可以手工单向拷**，但应用层没有共享开关。

## 触发条件与影响

- 项目或功能：同一台机器同时装两个版本，用户期望「教过一次另一边就会」。
- 环境与版本：本机 2026-10-18 首次实测并迁移。**2026-11-15 复测：国际版 118 个内容文件 / 索引 113 条 / 840K，国内版 77 / 75 / 516K** —— 迁移当时两边都是 70/70，28 天后已漂到差 41 个文件。
- 触发条件：换版本后 Agent 表现得像失忆，重复推导已有结论。
- 影响范围：任何「换客户端就掉经验」的场景；本次实际代价是 10-18 那轮从零重推了一遍 DSH 插件问题、还先问错了目标。

## 复现步骤

1. 前置条件：两个版本都装好、都跑过会话。
2. 操作或命令：

```sh
ls -la /c/Users/Admin/.qoder/memory /c/Users/Admin/.qoder-cn/memory
ls -la /c/Users/Admin/.qoder/projects /c/Users/Admin/.qoder-cn/projects
cat /c/Users/Admin/.qoder/settings.json /c/Users/Admin/.qoder-cn/settings.json   # 查有无 memory/path 指向对方
cmd //c "dir C:\\Users\\Admin\\.qoder-cn"                                        # 查有无 JUNCTION/SYMLINK
```

3. 预期结果：若共用，两边应指向同一 inode/联接。
4. 实际结果：两个独立目录树，无联接；会话历史 `.jsonl` 也各自一份。

## 证据

| 项 | 国际版 `.qoder` | 国内版 `.qoder-cn`（迁移前） |
|---|---|---|
| 用户级记忆（2026-10-18） | 70 个文件 / 460K | 2 个（本会话新写） |
| 项目级 `G--AIrenwu`（2026-10-18） | 7 条 | 1 条（本会话新写） |
| 该工作区会话历史（2026-10-18） | 10+ 个 `.jsonl` | 仅当次一个 |
| **用户级（2026-11-15 复测）** | **118 文件 / 索引 113 / 840K** | **77 / 75 / 516K** |
| **项目级（2026-11-15 复测）** | 8 / 8 | 8 / 8（已重新收敛） |
| **未入索引的文件（2026-11-15）** | **5 个** | **2 个** |

迁移后校验（脚本量数，不靠肉眼）：

```
用户级: 索引 70 条 / 内容文件 70 个
项目级: 索引 7 条 / 内容文件 7 个
diff -rq 源 目标 → 只剩 2 条 "Only in 国内版"（本会话自己写的两条）
```

## 根因分析

- 已确认的根因：两个版本各自用各自的安装根目录，记忆目录派生自根目录，天然隔离。
- 排除过的假设：「有环境变量或配置能改记忆根目录」——两份 `settings.json` 里只有 `enabledPlugins`（国际版另有 `mcpServers`/`providers`），**没有任何 memory 路径项**。
- 问题归属：环境或依赖（产品设计），非配置错误。

## 最小修复

单向拷入（只读国际版、不改动它，完全可回滚）：

```sh
cp -n /c/Users/Admin/.qoder/memory/*.md          /c/Users/Admin/.qoder-cn/memory/
cp -n /c/Users/Admin/.qoder/projects/G--AIrenwu/memory/*.md \
    /c/Users/Admin/.qoder-cn/projects/G--AIrenwu/memory/
```

- 必须用 `cp -n`（no-clobber）：否则会用旧索引覆盖掉本地新写的 `MEMORY.md`。
- 索引要**手工合并**，不是拷贝：以国际版 `MEMORY.md` 为基底，追加本地独有行，并在开头加一条「本次导入是快照不是联接」的说明。
- 拷完必做两项校验：①逐文件检查「有没有入索引」（`grep -q "(file)" MEMORY.md`）；②`diff -rq` 源与目标，确认差异只剩本地新增。

## 可复用规则

- 换版本 / 换机器后要「不失忆」，就按上面的 `cp -n` + 索引合并 + 两项校验走；**别用 `mklink /J` 做实时共用**，两边同时重写 `MEMORY.md` 索引会互相覆盖，且国内版新条目会污染国际版库。
- 校验一律用脚本数数，别用「看起来都在」。本次三处只有脚本能发现：国际版索引漏条目、同名不同内容的坑、以及 11-15 复测时**国内版自己又漏了 2 条索引**。
- **不要在索引里按位置描述来源**（「末尾三条是……新写的」这类话）。索引会持续追加，位置必然失效——11-15 实测两条这种说明都已指错行，只能改成「用 `diff -q` 判来源」。同理，任何写成「N/N 对齐」的数字都要带测量日期，否则下次读到就会被当成现状。
- **同名文件不等于重复文件**：`reference-zongce-weiji-table.md` 在用户级和项目级各有一份，**内容是两条不同记录**（一份记分口径、一份版式改造路线）。合并前必须 `diff`，不能按文件名去重。

## 适用范围与不适用范围

- 适用：本机 `.qoder` ↔ `.qoder-cn` 之间的记忆搬运；任何「两个客户端各存一份记忆」的迁移。
- 不适用：会话历史 `.jsonl` 的搬运（本条只搬记忆条目，不搬对话）；跨用户/跨机器的记忆同步（未验证）。

## 剩余风险

- **快照会漂移，已量化**：10-18 迁移时两边 70/70，11-15 复测已是国际版 118 / 国内版 77 —— 28 天差 41 个文件，且国内版**没有**自动追上国际版新增的 48 条。定期重跑 `diff -q` 只能发现差异，不会自动合并；重拷时要重新做索引合并与 orphan 检查，不能假设上次的方法一次有效。
- **索引漏条目是会复发的缺陷**（11-15 实测国内 2、国际 5），因为写记忆文件的动作和更新 `MEMORY.md` 的动作不绑定。任何「记忆库完整性」结论都必须现跑 orphan 检查，不能引用上次的 70/70。
- 顺带发现（与本条无关但需报备）：国际版 `C:\Users\Admin\.qoder\settings.json` 里**明文存了一把 API key**。本条记录不写它的值，只标位置。
