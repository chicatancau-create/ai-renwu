# 规则：技能库分「全量库」与「默认窗口」两层，默认只加载两个技能

## 一句话结论

本机 44+ 个技能全部放在 `D:\Skills`（唯一真源），但**各 Agent 的技能根一律指向 `D:\Skills-active`，
那里只有 `headroom` 与 `skill-router` 两条联接**；需要别的技能时由 `skill-router` 判定后
**直接 read 对应的 `SKILL.md`**，不往窗口里加东西。

## 触发条件与影响

- 用户 2026-11-15 定规（原话）：「以后这台笔记本上所有的 AI Agent 只默认开启两个工具：
  1. 省 token 的工具 2. 判断本次任务还应开启哪些工具的工具」。理由是「工具太多…有点负担」。
- 影响：任何 Agent 开工时看到的用户技能只有两条，其余技能的 description **永不进上下文**。
- 例外：各 Agent **自带**技能（DSH 的 office/memory-*、Codex 的 `.system`、TRAE builtin 等）不受此规矩约束，
  用户明确说「自带的我不管」。

## 目录与接法（实测）

| 层 | 路径 | 内容 |
|---|---|---|
| 全量库 | `D:\Skills` | 44 个技能实体 + README/THIRD_PARTY/BACKUP_SCOPE；已 `git init`，双远端私有备份 |
| 默认窗口 | `D:\Skills-active` | 只有 `headroom`、`skill-router` 两条 Junction → `\\?\D:\Skills\<名>` |
| 停用区 | `D:\Skills-disabled` | 停用技能移这里，不参与发现 |
| 镜像 | `D:\Skills-mirror` | 自愈盾的本地修复源，**不是归档**，别删 |
| 运行态 | `D:\AI-Tool-State` | `AI_SHARED_SKILLS_STATE_DIR`；缓存/日志/输出写这里，**不许写进技能源目录** |

12 个技能根的接法（`ops.py status` 可回读）：

- **整目录 Junction → `D:\Skills-active`**：`.claude\skills`、`.agents\skills`（DSH 读这个）、
  `.config\opencode\skills`、`.workbuddy\skills`
- **真实目录 + 两条逐项联接**：`.workbuddy-ai\skills`、`.openclaw\skills`、`.codex\skills`（保留 `.system`）、
  `.qoder\skills`、`.qoder-cn\skills`、`.herdsman\work\skills`、`.dsh\skills`
- **`.cc-switch\skills` 不能搬**：它是 cc-switch 自己的存储（`skillStorageLocation=cc_switch`），
  DB 的 `directory` 列引用它；只在里面加两条联接。

## 证据

- **最直接的证据是本会话自身**：改接完成后，DSH 的技能目录从 50 个用户技能**掉到只剩
  `headroom` + `skill-router`**（外加 DSH 自带的 office/memory-*/official-plugins 等）。
  这证明 DSH 确实经 `.agents\skills` → `D:\Skills-active` 读取，规矩真实生效。
- `ops.py status` 回读 12 个技能根：claude/agents-DSH/opencode/workbuddy 为整目录 Junction →
  `\\?\D:\Skills-active` 且 2/2 可读；workbuddy-ai/openclaw/qoder/qoder-cn/herdsman/dsh 为真实目录 2/2；
  codex 2/3（多出的是 `.system`）；cc-switch 11/11（9 个自有存储 + 2 条新联接）。
- `router.py doctor` → `OK: 库/窗口/联接/命名全部正常`；catalog 53 条，与 SKILL.md 索引条数双向差集为空。
- `audit_all.py`（11 组 57 项只读体检）→ **FAIL=0 / PASS=51 / WARN=5**，
  WARN 全是历史日志与 WorkBuddy 旧损坏，与技能发现无关。
- cc-switch 侧回读：`local:headroom`、`local:skill-router` 两行 12 个 `enabled_*` 全为 1，其余 9 行全 0。

## 根因分析

- 已确认：技能发现是**扫目录**，没有跨工具统一的 enable 开关；要控制「默认加载哪些」只能控制目录内容。
- 排除过的假设：靠 cc-switch 的 `enabled_<agent>` 列统一管（实测它只覆盖自己表里那 9 个技能）；
  靠会话中改目录让 Agent 重新发现（多数 Agent 会话开始就快照了列表）。
- 问题归属：本次修改引入（新建的两层架构），非既有故障。

## 为什么路由靠「读文件」而不是「改目录」

多数 Agent **在会话开始时快照技能列表**，会话中改目录它看不见。
直接 `read D:\Skills\<目录名>\SKILL.md` 对任何 Agent 都即时生效，且不必把别的 description 塞进上下文。
长期常驻需求才用 `router.py pin`。

## cc-switch 管不到统一库（别指望它）

`cc-switch.db` 的 `skills` 表有 12 个开关列
（`enabled_claude/codex/gemini/opencode/hermes/grokbuild/mcode/agy/kimi/dsh/copilot/workbuddy`），
但**只覆盖它自己表里那 9 个技能**（`local:dws`、`local:docx` 等），统一库的技能不在表里。
所以「默认只开两个」必须靠目录层实现，cc-switch 侧只是把 `local:headroom`、`local:skill-router`
两行 12 个开关置 1、其余置 0 做策略对齐。

## 运维入口（都在 `D:\Skills\skill-router\`）

```
python D:\Skills\skill-router\ops.py status     # 代理/接线/窗口/12 个根/库计数
python D:\Skills\skill-router\ops.py skills     # router.py sync + doctor
python D:\Skills\skill-router\ops.py backup now # 立刻提交并推两个远端
python D:\Skills\skill-router\router.py match "<任务描述>"   # 看该开哪些技能
python D:\Skills\skill-router\router.py show <name>          # 按 frontmatter name 也能解析到目录
```

`router.py` 的打分：触发词命中 +3.0+len*0.3、name 命中 +6.0、token 重叠 +0.35，
**噪声闸 score>=2.0 才展示、最多 6 条**（无闸时会塞一堆低分噪声）。
实测「excel 报表整理做成 ppt」→ xlsx 8.8 / pptx 4.2；「动态网页落地页+滚动动画」→ landing-page-design 18.7。

## 可复用规则

1. 新增技能**只往 `D:\Skills` 放**，然后 `router.py sync`；**不要 pin 进 `D:\Skills-active`**，
   除非用户明确要求长期常驻。
2. 目录名与 frontmatter `name` 应同名；已知例外：`reverse-trace`→`spider-king`（自带闸门硬校验，改了会多 ERROR）、
   `reverse-wechat-miniapp`→`wechat-miniapp-reverse`、`brave-web-search`→`web-search`、
   三个厂商前缀目录（checkpoint / requirement-translator / frontend-slides）。`router.py show` 对例外全部正确解析。
3. **WorkBuddy 会往它的技能根写状态文件**（`.disable_to_model_invocation_migration.json`、
   `.model_invocation_to_override_migration.json`）。改接技能根时**只能 inject（加/删技能联接），
   绝不能 rmdir 根目录重建**，否则会把应用状态搬走。统计技能数时只数目录。

## 适用范围与不适用范围

- 适用：本机所有读 `skills/` 目录发现技能的 Agent。
- 不适用：各 Agent 自带技能；插件市场目录包（`.workbuddy\connectors-marketplace\*` 有 870 个 SKILL.md，
  但 `connectors\skills` 是空的，说明没安装为技能，不算用户技能）。

## 剩余风险

- `D:\Skills-active` 是联接，**用资源管理器删它会连真源一起删**，见
  [[踩坑-删联接目录会跟随联接回收真源须靠回收站元数据取证]]。
- 另一个 AI 仍在搬 `D:\_整理`；`D:\QoderToolkit` 已建总联接 → `D:\_整理\04-AI工具包\QoderToolkit`
  隔离这层风险（`qoder-toolkit\SKILL.md` 正文硬编码了 4 处 `D:\QoderToolkit\...`）。
